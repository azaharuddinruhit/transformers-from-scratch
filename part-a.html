Part A

The big picture

    Introduction: what is an LLM?

    You will be able to
    • Say in one sentence what an LLM computes.
    • Turn a list of scores (logits) into probabilities with softmax, by hand.
    • Explain why predicting one token at a time is enough to model whole texts.

    The guide follows one prompt, “the cat sat on the ▢”, through the whole model. Here you only see the two ends: the text goes in, and “mat” comes out as the most probable next token.

    A large language model is a function with one job: given some text, say how likely each possible next piece of text is. Everything else, from answering questions to writing code, comes from running that one function again and again.

    • Token: the unit of text the model reads and writes. Usually a word or a piece of a word.
    • Vocabulary: the fixed list of all tokens the model knows, typically 30,000 to 200,000 entries.
    • Next-token prediction: the model outputs one probability per vocabulary entry.
    • Autoregressive generation: pick a token, append it to the input, predict again.
    • Parameters: the numbers inside the function (millions to trillions) that training adjusts.
    • Training changes the parameters so good predictions become likelier. Inference uses the finished parameters without changing them.

    The equations, and the reasoning behind them

    Step 1: scores. For the next position the network outputs one real number per vocabulary entry, called a logit and written z_v for entry v. A higher logit means “more plausible here”. But logits can be negative and do not add up to anything in particular, so they are not probabilities yet.

    Step 2: turn scores into probabilities. We need numbers that are positive and sum to 1. Softmax gets there in two moves: exponentiate every logit, which makes it positive and keeps the ranking, then divide by the total, which makes the sum 1.

    p(w_{t+1}=v \mid w_1,\dots,w_t)=\mathrm{softmax}(z)_v=\frac{e^{z_v}}{\sum_{v'=1}^{n_{\text{vocab}}} e^{z_{v'}}}

    w_t is the token at position t. v and v' run over the n_{\text{vocab}} vocabulary entries; the bar “|” reads “given”.

    Why the exponential?
    Dividing each logit by the plain sum would fail: logits can be negative, and the sum can be zero. The exponential is always positive. It also gives logits a precise meaning: a gap of 1 between two logits always means a probability ratio of e\approx2.72, wherever the two logits sit. That is why adding the same number to every logit changes nothing; only the gaps matter.

    Step 3: from one token to a whole text. The probability of a sequence is the probability of its first token, times the probability of the second given the first, and so on. This is the chain rule of probability. It is exact, and it is the reason a next-token predictor is a model of entire texts.

    p(w_1,\dots,w_T)=\prod_{t=1}^{T}p(w_t\mid w_{\lt t})

    T is the number of tokens and w_{\lt t} means “all tokens before position t”.

    Worked example

    Three tokens with logits z=[2.0,\;1.0,\;0.1].

    Exponentiate: e^{2.0}=7.3891,\; e^{1.0}=2.7183,\; e^{0.1}=1.1052, which sum to 11.2125.

    Divide each by the sum: p=[0.6590,\;0.2424,\;0.0986]. They add up to 1.

    Check the “gap” rule: the first two logits differ by 1, and 0.6590/0.2424=2.72.

    Three candidate tokens get scores 2.0, 1.0 and 0.1. Softmax turns those into roughly 66%, 24% and 10%. The gaps between scores matter, not the scores themselves: adding 5 to every score changes nothing.

    In Python: softmax, then sampling
    Runs on its own · Python 3 + NumPy
    import numpy as np


def softmax(z):
    z = np.asarray(z, dtype=float)
    e = np.exp(z - z.max())  # subtracting the max changes nothing but avoids overflow
    return e / e.sum()


z = np.array([2.0, 1.0, 0.1])
p = softmax(z)
print("p              =", p.round(4))
print("sum            =", round(p.sum(), 6))
print("p[0] / p[1]    =", round(p[0] / p[1], 4))  # a gap of 1 gives a ratio of e
print("softmax(z + 5) =", softmax(z + 5).round(4))  # only the gaps matter

# Why subtract the max: exp(1000) overflows to infinity
big = np.array([1000.0, 999.0])
with np.errstate(over="ignore", invalid="ignore"):
    naive = np.exp(big) / np.exp(big).sum()
print("naive          =", naive)
print("stable         =", softmax(big).round(4))

# Sampling: draw tokens in proportion to their probabilities
rng = np.random.default_rng(0)
tokens = np.array(["mat", "sofa", "floor"])
draws = rng.choice(tokens, size=1000, p=p)
print("1000 draws     =", {str(t): int((draws == t).sum()) for t in tokens})

# Output:
# p              = [0.659  0.2424 0.0986]
# sum            = 1.0
# p[0] / p[1]    = 2.7183
# softmax(z + 5) = [0.659  0.2424 0.0986]
# naive          = [nan nan]
# stable         = [0.7311 0.2689]
# 1000 draws     = {'mat': 637, 'sofa': 268, 'floor': 95}

    Beginner note

    The model never outputs a word directly. It outputs a list of numbers as long as the vocabulary, and a separate, simple piece of code chooses a token from that list.

    Common misconceptions

    • “It looks answers up in a database.” There is no stored text. There are only parameters, and the text is recomputed from them one token at a time.
    • “It predicts the next word.” It predicts a probability distribution over tokens, and tokens are often pieces of words.
    • “It learns while I chat with it.” During inference the parameters are frozen. It only appears to remember because the whole conversation is fed back in as input each time.
    • “Next-token prediction is too simple to be useful.” Predicting the next token of a proof, a program or a dialogue well requires modelling a great deal about what the text is describing.

    Key takeaways

    • An LLM is a function from “text so far” to one probability per vocabulary entry.
    • Softmax = exponentiate, then divide by the sum. Only the gaps between logits matter.
    • The chain rule turns next-token probabilities into the probability of a whole text.
    • Generation is a loop: predict, pick, append, repeat.

    Check yourself

    1. You add 10 to every logit before softmax. What happens to the probabilities?

    Softmax depends only on the differences between logits, and adding a constant leaves every difference unchanged.

    2. What does the model output for one position?

    The output is a full distribution. Choosing one token from it is a separate step (decoding).

    3. Two logits differ by 1. How do their probabilities compare?

    A gap of 1 in logits is always a ratio of e in probability, whatever the other logits are.

    Why Transformers? The idea behind the 2017 paper

    Builds on The idea of next-token prediction from . It helps to have heard of recurrent networks (RNNs), but it is not required.

    In an RNN, information from “cat” must survive three updates to influence the prediction after “the cat sat on the”. In a Transformer the last position can look at “cat” directly.

    Everything in this guide descends from one eleven-page paper by Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser and Polosukhin, presented at the NIPS conference in 2017. It was not about chatbots. It was about machine translation, and its claim was narrow and bold: you can drop recurrence and convolution entirely and build a translation model from attention alone, and it will be both better and much faster to train.

    You do not need to understand the paper yet. This section explains the problem it solved, so that the components in the following sections have a purpose. The paper’s own model is covered in , once you know all the parts.

    The problem it solved

    Before 2017 the standard tool for sequences was the recurrent neural network (RNN, usually an LSTM). An RNN reads one token at a time and carries a single “memory” vector forward. That has two costs. Training cannot be parallelised along the sequence, because step 50 needs the result of step 49. And information from an early word has to survive dozens of updates to reach a late one. Attention had already been added to RNNs as a helper (Bahdanau et al., 2014). The 2017 paper kept the helper and removed the RNN.

    RNNword 1 → 2 → 3 → … → n
    :
    n − 1 stepsbetween the first and last word; computed one after another
    Transformerevery word ↔ every word
    :
    1 stepbetween any two words; all positions computed in parallel

    What it costs

    The paper compared the two kinds of layer directly. For a sequence of T tokens and width d_{\text{model}} (the paper writes n and d):

    Layer typeWork per layerSequential stepsLongest path between two positions
    Self-attentionO(T^{2}\cdot d_{\text{model}})O(1)O(1)
    RecurrentO(T\cdot d_{\text{model}}^{2})O(T)O(T)

    d_{\text{model}} is the length of the vector the model keeps for each token; you will meet it properly in . Self-attention compares all T^2 pairs of tokens, each comparison costing about d_{\text{model}}. A recurrent layer takes T steps, each a d_{\text{model}}\times d_{\text{model}} matrix product.

    The point: Self-attention is cheaper per layer only while sequences are short relative to the width. Do this: Raise the sequence length until the two bars are equal. Watch for: They meet at T = d_{\text{model}}. Beyond that, the T² term dominates.

    These are the growth rates from Table 1 of the paper with the constants dropped, so compare the two rows with each other and do not read them as measured costs.
    What just happened? Self-attention does less arithmetic per layer whenever the sequence is shorter than the model is wide, which was true for the sentences the paper translated. More important are the other two columns: all positions are computed at once, and any two words are one step apart. The price appears when T grows past d_{\text{model}}: the T^2 term takes over. That is the long-context cost you will meet again in and .

    What the model is made of: the road ahead

    Removing recurrence leaves gaps that other parts have to fill. Each gets its own section:

    • Tokens and embeddings turn text into vectors ().
    • Positional information restores word order, which an RNN had for free ().
    • Self-attention lets every token read every other token (), several times in parallel ().
    • A feed-forward network, residual connections and normalisation turn attention into a trainable block ().
    • A stack of blocks plus an output layer is the complete model ().

    Common misconceptions

    • “The paper invented attention.” Attention was already used alongside RNNs. The contribution was a model built on it with no recurrence at all, plus multi-head attention and the surrounding recipe.
    • “Attention is literally all you need.” The model also needs feed-forward layers, residual connections, normalisation, embeddings and positional information. Remove any of them and it stops working.
    • “The paper introduced large language models.” It introduced a translation model of at most 213 million parameters. Pretraining on raw text and scaling up came later.

    Key takeaways

    • RNNs process tokens one after another: no parallelism along the sequence, and long paths between distant words.
    • Self-attention connects every pair of tokens in one step and computes all positions in parallel.
    • The price is work that grows with the square of the sequence length.
    • The 2017 paper introduced the recipe; modern LLMs keep its core and change a few details.

    Check yourself

    1. Why can an RNN not be trained in parallel along the sequence?

    Step 50 takes the memory vector produced by step 49 as input, so the steps must run in order.

    2. When does a self-attention layer do less arithmetic than a recurrent layer?

    The costs are T^2 d_{\text{model}} against T\,d_{\text{model}}^2. They are equal at T = d_{\text{model}}.

    3. What was the 2017 paper’s model built for?

    It was an encoder–decoder translation model. Decoder-only language models came afterwards.

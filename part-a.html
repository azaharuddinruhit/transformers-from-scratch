The big picture

    Introduction: what is an LLM?

    You will be able to
    • Say in one sentence what an LLM computes.
    • Turn a list of scores (logits) into probabilities with softmax, by hand.
    • Explain why predicting one token at a time is enough to model whole texts.

    The guide follows one prompt, “the cat sat on the ▢”, through the whole model. Here you only see the two ends: the text goes in, and “mat” comes out as the most probable next token.

    A large language model is a function with one job: given some text, say how likely each possible next piece of text is. Everything else, from answering questions to writing code, comes from running that one function again and again.

    • Token: the unit of text the model reads and writes. Usually a word or a piece of a word.
    • Vocabulary: the fixed list of all tokens the model knows, typically 30,000 to 200,000 entries.
    • Next-token prediction: the model outputs one probability per vocabulary entry.
    • Autoregressive generation: pick a token, append it to the input, predict again.
    • Parameters: the numbers inside the function (millions to trillions) that training adjusts.
    • Training changes the parameters so good predictions become likelier. Inference uses the finished parameters without changing them.

    The equations, and the reasoning behind them

    Step 1: scores. For the next position the network outputs one real number per vocabulary entry, called a logit and written z_v for entry v. A higher logit means “more plausible here”. But logits can be negative and do not add up to anything in particular, so they are not probabilities yet.

    Step 2: turn scores into probabilities. We need numbers that are positive and sum to 1. Softmax gets there in two moves: exponentiate every logit, which makes it positive and keeps the ranking, then divide by the total, which makes the sum 1.

    p(w_{t+1}=v \mid w_1,\dots,w_t)=\mathrm{softmax}(z)_v=\frac{e^{z_v}}{\sum_{v'=1}^{n_{\text{vocab}}} e^{z_{v'}}}

    w_t is the token at position t. v and v' run over the n_{\text{vocab}} vocabulary entries; the bar “|” reads “given”.

    Why the exponential?
    Dividing each logit by the plain sum would fail: logits can be negative, and the sum can be zero. The exponential is always positive. It also gives logits a precise meaning: a gap of 1 between two logits always means a probability ratio of e\approx2.72, wherever the two logits sit. That is why adding the same number to every logit changes nothing; only the gaps matter.

    Step 3: from one token to a whole text. The probability of a sequence is the probability of its first token, times the probability of the second given the first, and so on. This is the chain rule of probability. It is exact, and it is the reason a next-token predictor is a model of entire texts.

    p(w_1,\dots,w_T)=\prod_{t=1}^{T}p(w_t\mid w_{\lt t})

    T is the number of tokens and w_{\lt t} means “all tokens before position t”.

    Worked example

    Three candidate tokens get scores 2.0, 1.0 and 0.1. Softmax turns those into roughly 66%, 24% and 10%. The gaps between scores matter, not the scores themselves: adding 5 to every score changes nothing.

    Work through the exact numbers

    Three tokens with logits z=[2.0,\;1.0,\;0.1].

    Exponentiate: e^{2.0}=7.3891,\; e^{1.0}=2.7183,\; e^{0.1}=1.1052, which sum to 11.2125.

    Divide each by the sum: p=[0.6590,\;0.2424,\;0.0986]. They add up to 1.

    Check the “gap” rule: the first two logits differ by 1, and 0.6590/0.2424=2.72.

    In Python: softmax, then sampling
    Runs on its own · Python 3 + NumPy
    import numpy as np


def softmax(z):
    z = np.asarray(z, dtype=float)
    e = np.exp(z - z.max())  # subtracting the max changes nothing but avoids overflow
    return e / e.sum()


z = np.array([2.0, 1.0, 0.1])
p = softmax(z)
print("p              =", p.round(4))
print("sum            =", round(p.sum(), 6))
print("p[0] / p[1]    =", round(p[0] / p[1], 4))  # a gap of 1 gives a ratio of e
print("softmax(z + 5) =", softmax(z + 5).round(4))  # only the gaps matter

# Why subtract the max: exp(1000) overflows to infinity
big = np.array([1000.0, 999.0])
with np.errstate(over="ignore", invalid="ignore"):
    naive = np.exp(big) / np.exp(big).sum()
print("naive          =", naive)
print("stable         =", softmax(big).round(4))

# Sampling: draw tokens in proportion to their probabilities
rng = np.random.default_rng(0)
tokens = np.array(["mat", "sofa", "floor"])
draws = rng.choice(tokens, size=1000, p=p)
print("1000 draws     =", {str(t): int((draws == t).sum()) for t in tokens})

# Output:

    Beginner note

    The model never outputs a word directly. It outputs a list of numbers as long as the vocabulary, and a separate, simple piece of code chooses a token from that list.

    Common misconceptions

    • “It looks answers up in a database.” There is no stored text. There are only parameters, and the text is recomputed from them one token at a time.
    • “It predicts the next word.” It predicts a probability distribution over tokens, and tokens are often pieces of words.
    • “It learns while I chat with it.” During inference the parameters are frozen. It only appears to remember because the whole conversation is fed back in as input each time.
    • “Next-token prediction is too simple to be useful.” Predicting the next token of a proof, a program or a dialogue well requires modelling a great deal about what the text is describing.

    Key takeaways

    • An LLM is a function from “text so far” to one probability per vocabulary entry.
    • Softmax = exponentiate, then divide by the sum. Only the gaps between logits matter.
    • The chain rule turns next-token probabilities into the probability of a whole text.
    • Generation is a loop: predict, pick, append, repeat.

    To predict “mat” after “the cat sat on the”, a model has to turn numbers into other numbers, and it has to learn how from examples, because nobody can write the rules by hand. A neural network is the simplest machine that does both. An LLM is a very large one.

    A neural network is a function built from many small, identical pieces. Each piece does almost nothing. What the network computes depends on its weights: numbers that start out random and are adjusted, a little at a time, until the outputs are right. This section covers the pieces, then the adjusting.

    One neuron

    A neuron takes a list of numbers and returns one number. It multiplies each input by a weight, adds the results, adds one more number called the bias, and passes the total through an activation function:

    \text{output}=\tanh(x\cdot w+b)

    x is the list of inputs. w is the list of weights, one per input. b is the bias. x\cdot w is their dot product. \tanh is one common activation: it squeezes any number into the range −1 to 1.

    The weights say how much each input matters, and in which direction. The bias shifts the point at which the neuron switches from low to high.

    Worked example: one neuron

    With inputs 1 and 2, weights 0.5 and −1 and a bias of 0.5, the neuron adds up to −1 and outputs about −0.76. Change one weight and the output can flip to +0.76. Learning means finding good weights.

    Work through the exact numbers

    Inputs x=[1,2], weights w=[0.5,-1], bias b=0.5. The weighted sum is 1\times0.5+2\times(-1)+0.5=-1, and the output is \tanh(-1)=-0.762. Raise the second weight from −1 to 0 and the sum becomes 1, so the output flips to 0.762.

    Layers, and why depth helps

    A layer is many neurons reading the same inputs, each with its own weights. Their weights stack into a matrix W, so a whole layer is one matrix multiplication followed by the activation:

    h=\tanh(xW+b)

    W has one column of weights per neuron. b now holds one bias per neuron. h is the list of the neurons’ outputs, which becomes the input of the next layer.

    A network with layers between its input and its output is called deep, and those middle layers are hidden layers. Early layers detect simple patterns, and later layers combine them into more complex ones. Every model in this guide is built this way: a Transformer is a few dozen layers of a particular design.

    Why is the activation needed?
    Without it, two layers would compute (xW_1)W_2=x(W_1W_2), which is just one matrix. A stack of any depth would then do no more than a single layer: it could only draw straight lines through the data. The activation bends the output of each layer, and that is what lets a network fit curved patterns. The interactive below shows the difference.

    How a network learns

    Training is one loop, repeated many times:

    1. Predict. Feed in some examples and compute the outputs. This is the forward pass.
    2. Measure. Compare the outputs with the right answers. The loss is one number that says how wrong they were: 0 is perfect, larger is worse.
    3. Find the slopes. For every weight, work out whether nudging it up would raise or lower the loss, and by how much. This list of slopes is the gradient, and the method that computes it, working back from the loss through each layer, is backpropagation.
    4. Update. Move every weight a small step in the direction that lowers the loss. This is gradient descent.
    \theta\leftarrow\theta-\eta\,\nabla_\theta\mathcal{L}

    \theta stands for all the weights and biases. \mathcal{L} is the loss. \nabla_\theta\mathcal{L} is the gradient. \eta is the learning rate, the size of the step.

    No step is clever. Each one makes the network slightly less wrong on the examples it just saw, and thousands of them add up to a network that works.

    Training in practice

    • Training and validation data. Keep some examples aside and never train on them. The loss on those validation examples tells you whether the network has learned the pattern or only memorised its training examples.
    • Overfitting. If the training loss keeps falling while the validation loss rises, the network is memorising, noise included. More data is the best cure; a smaller network or stopping earlier also helps.
    • Batches and epochs. Real datasets are too large to use all at once, so each step uses a small random batch. One pass through the whole dataset is an epoch.
    • Learning rate. Too small and training crawls. Too large and the loss jumps around or blows up.

    From this to an LLM

    An LLM is the same loop at a very different scale. Its inputs are tokens, its layers are Transformer blocks, its output is a probability for every possible next token, and its loss measures how surprised it was by the token that really came next. covers that loss.

    Common misconceptions

    • “A neural network works like a brain.” The name is historical. A neuron here is a weighted sum and a squashing function, nothing more.
    • “Someone programs what each neuron detects.” Nobody sets the weights. They start random, and training finds them.
    • “A training loss near zero means the network is good.” It may have memorised the training data. Only the validation loss tells you.
    • Pitfall: judging a model on the data it was trained on.

    Key takeaways

    • A neuron computes a weighted sum of its inputs plus a bias, then applies an activation.
    • A layer is many neurons at once: a matrix multiplication followed by the activation. Stacked layers make a deep network.
    • Without a non-linear activation, any number of layers collapses into one.
    • Training repeats one loop: predict, measure the loss, compute the gradient by backpropagation, step the weights downhill.
    • Validation loss rising while training loss falls is overfitting.

    Generative AI: the big picture

    • Explain why the Transformer is a network and not a way of generating, and where it is used.

    Builds on Next-token prediction and the chain rule from , and the classifier you trained in .

    The network in answered a question about a point it was given: which class is this? An LLM is asked a different question: what could come next? Asked again and again, it writes “the cat sat on the mat” instead of judging it.

    Most machine learning in products used to sort things: spam or not, fraud or not, which product a photo shows. Those models are classifiers. A generative model does something else: it produces new examples that look as if they came from its training data, such as text, code, images or audio. “Generative AI” is the name for models of the second kind, usually steered by a prompt.

    Sorting versus creating

    • A classifier takes an example and returns a label: an email in, “spam” out. Its output is small, one probability per class.
    • A generative model returns an example: a prompt in, a paragraph or an image out. Its output is large, thousands of tokens or millions of pixel values, and every part has to fit with every other part.

    What does each kind of model have to learn? A classifier only needs the boundary between the classes. It never has to know what a typical email looks like, only which side of the line one falls on. A generator has to know what the data itself looks like, so that it can draw new examples from it. In the language of probability:

    \text{classifier: } p(\text{label}\mid\text{example})\qquad \text{generative model: } p(\text{example})\qquad \text{with a prompt: } p(\text{example}\mid\text{prompt})

    An example is, say, a text or an image; a label is a class such as “spam”. p(\text{example}) is high for examples that look like the training data and low for everything else.

    Training a generative model makes its training examples probable. Generating means drawing a new example from the learned distribution, which is called sampling.

    Two ways to make something large

    Choosing every token of a paragraph, or every pixel of an image, in one go is too hard, because the parts depend on each other. Every successful generator breaks the job into many small predictions. There are two main recipes.

    One piece at a time (autoregressive). Predict the first token, then the second given the first, and so on. Each step is a choice over the vocabulary, the kind of prediction neural networks are good at. This is the chain rule from , and it is how LLMs work:

    p(w_1,\dots,w_T)=\prod_{t=1}^{T}p(w_t\mid w_{\lt t})

    w_t is the token at position t, w_{\lt t} is every token before it, and T is the number of tokens.

    Remove noise, step by step (diffusion). Start from pure random noise the size of the output, say an image. A network predicts which part of it is noise, and a little of that is removed. After many such steps, often 20 to 50, a clean image remains. Every step updates the whole image at once. Most image, video and audio generators work this way; shows how.

    Older recipes. A GAN (generative adversarial network) trains a generator against a second network that tries to tell its output from real data. A VAE (variational autoencoder) learns to squeeze an example into a short code and rebuild it, then generates by rebuilding random codes. Both make a sample in a single pass. For images, diffusion has largely replaced them.

    Worked example: a generator that learns by counting

    Train on three names: ana, anna and nina. The “model” looks at one letter of context and counts which letter came next. A dot marks the start and the end of a name.

    After a, the names end three times and continue with n twice, so the model ends a name after a with probability 3/5. Multiplying the step probabilities gives about a 10% chance of generating “ana”, and about 3% for “nana”, a name it never saw: each of its steps was seen, just not in that order.

    Work through the exact numbers

    After the start: a twice, n once, so p(\text{a}\mid\text{start})=2/3. After a: the end three times, n twice, so p(\text{end}\mid\text{a})=3/5 and p(\text{n}\mid\text{a})=2/5. After n: a three times, n once, i once, so p(\text{a}\mid\text{n})=3/5.

    The chain rule gives the probability of generating “ana”: \tfrac23\times\tfrac25\times\tfrac35\times\tfrac35=0.096.

    And of “nana”, which is not in the training list: \tfrac13\times\tfrac35\times\tfrac25\times\tfrac35\times\tfrac35=0.0288. The model has never seen it, but every step in it is one it has seen.

    “an” is impossible: no training name ends in n, so p(\text{end}\mid\text{n})=0.

END = "."  # marks the start and the end of a name


def train(k):
    """For every run of k letters, count which letter came next."""
    table = defaultdict(Counter)
    for name in NAMES:
        s = END * k + name + END
        for i in range(k, len(s)):
            table[s[i - k:i]][s[i]] += 1
    return table


def generate(table, k, rng):
    """Draw one letter at a time from the counts until the end marker is drawn."""
    name = ""
    while True:
        counts = table[(END * k + name)[-k:]]
        letter = rng.choices(list(counts), weights=list(counts.values()))[0]
        if letter == END:
            return name
        name += letter


table = train(2)
after = table["ma"]
total = sum(after.values())
print("after 'ma':", {c: f"{n}/{total}" for c, n in after.most_common()})

rng = random.Random(0)
known = set(NAMES)
for k in (1, 2, 3, 4):
    table = train(k)
    names = [generate(table, k, rng) for _ in range(1000)]
    copies = sum(n in known for n in names) / len(names)
    print(f"context {k}: {copies:5.1%} copies   e.g. {' '.join(names[:6])}")

    Generated names, newest first
    What is simplified: the “model” is a table of counts, not a neural network. For each run of letters in 162 first names, it counts which letter came next.     What just happened? Each letter was drawn from the bars, as an LLM draws each token, and the name ended when the end marker was drawn. With 1 letter of context the model knows too little, and most names are unpronounceable. With 2 letters most names are new and some sound plausible. With 3 or 4 letters the names look real because most are copies: each context is so specific that only one training name continues it. That is memorising, the generative form of the overfitting in . A useful generator sits in between, producing outputs that are new but plausible. LLMs get there with a network that learns patterns shared across billions of examples, not a table.

    Where the Transformer sits

    Two choices define a generative model, and they are independent:

    • the recipe: what the network is trained to predict, and how a sample is built from those predictions (one token at a time, or step-by-step denoising);
    • the network: the architecture that makes each prediction, such as a CNN or a Transformer.

    The Transformer is a network, not a recipe. LLMs pair it with the autoregressive recipe. Many recent image generators pair it with diffusion, in place of the convolutional network that earlier ones used. Speech and vision models use it too. That is why learning the Transformer pays off well beyond text.

    Common misconceptions

    • “Generative AI means chatbots.” Text is one kind of output. The same ideas produce code, images, audio and video.
    • “A generative model stitches together pieces of its training data.” It samples from learned probabilities, so most outputs are new. It can still memorise and repeat training data, especially text it saw many times, as the 4-letter setting shows.
    • “Diffusion models and Transformers are rival technologies.” One is a recipe and the other is a network. Many diffusion models have a Transformer inside.
    • Pitfall: treating fluent output as checked output. A generator is trained to be plausible, not to be true.

    Key takeaways

    • A classifier returns a label for an example; a generative model returns a new example.
    • Generators break a large output into many small predictions: one token at a time (LLMs) or one denoising step at a time (diffusion).
    • The Transformer is a network; autoregressive generation and diffusion are recipes. They combine freely.
    • A good generator is new but plausible. Too little context gives nonsense; too much gives copies of the training data.

    Builds on The idea of next-token prediction from . It helps to have heard of recurrent networks (RNNs), but it is not required.

    In an RNN, information from “cat” must survive three updates to influence the prediction after “the cat sat on the”. In a Transformer the last position can look at “cat” directly.

    Everything in this guide descends from one eleven-page paper by Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser and Polosukhin, presented at the NIPS conference in 2017. It was not about chatbots. It was about machine translation, and its claim was narrow and bold: you can drop recurrence and convolution entirely and build a translation model from attention alone, and it will be both better and much faster to train.

    You do not need to understand the paper yet. This section explains the problem it solved, so that the components in the following sections have a purpose. The paper’s own model is covered in , once you know all the parts.

    What came before

    The Transformer was not the first kind of neural network () used for language. Each earlier kind was built for a different shape of data:

    NetworkBuilt forHow it reads its inputLimit for text
    MLP (fully connected)Inputs of a fixed size, such as a row of a tableAll inputs at once, each with its own weightNo sense of order, and no way to take text of any length
    CNN (convolutional)ImagesSlides small filters over neighbouring valuesEach layer sees only a small window, so distant words need many layers to meet
    RNN (recurrent), including the LSTMSequences: text and speechOne item at a time, carrying a memory vector forwardSlow to train, and early tokens fade from the memory
    TransformerSequences, and now most kinds of dataEvery position looks at every other position directlyWork grows with the square of the length

    The problem it solved

    Before 2017 the standard tool for sequences was the recurrent neural network (RNN, usually an LSTM). An RNN reads one token at a time and carries a single “memory” vector forward. That has two costs. Training cannot be parallelised along the sequence, because step 50 needs the result of step 49. And information from an early word has to survive dozens of updates to reach a late one. Attention had already been added to RNNs as a helper (Bahdanau et al., 2014). The 2017 paper kept the helper and removed the RNN.

    RNNword 1 → 2 → 3 → … → n
    :
    n − 1 stepsbetween the first and last word; computed one after another
    Transformerevery word ↔ every word
    :
    1 stepbetween any two words; all positions computed in parallel

    What it costs

    The paper compared the two kinds of layer directly. For a sequence of T tokens and width d_{\text{model}} (the paper writes n and d):

    Layer typeWork per layerSequential stepsLongest path between two positions
    Self-attentionO(T^{2}\cdot d_{\text{model}})O(1)O(1)
    RecurrentO(T\cdot d_{\text{model}}^{2})O(T)O(T)

    d_{\text{model}} is the length of the vector the model keeps for each token; you will meet it properly in . Self-attention compares all T^2 pairs of tokens, each comparison costing about d_{\text{model}}. A recurrent layer takes T steps, each a d_{\text{model}}\times d_{\text{model}} matrix product.

    What just happened? Self-attention does less arithmetic per layer whenever the sequence is shorter than the model is wide, which was true for the sentences the paper translated. More important are the other two columns: all positions are computed at once, and any two words are one step apart. The price appears when T grows past d_{\text{model}}: the T^2 term takes over.     What the model is made of: the road ahead

    Removing recurrence leaves gaps that other parts have to fill. Each gets its own section:

    • Tokens and embeddings turn text into vectors ().
    • Positional information restores word order, which an RNN had for free ().
    • Self-attention lets every token read every other token (), several times in parallel ().
    • A feed-forward network, residual connections and normalisation turn attention into a trainable block ().
    • A stack of blocks plus an output layer is the complete model ().

    Common misconceptions

    • “The paper invented attention.” Attention was already used alongside RNNs. The contribution was a model built on it with no recurrence at all, plus multi-head attention and the surrounding recipe.
    • “Attention is literally all you need.” The model also needs feed-forward layers, residual connections, normalisation, embeddings and positional information. Remove any of them and it stops working.
    • “The paper introduced large language models.” It introduced a translation model of at most 213 million parameters. Pretraining on raw text and scaling up came later.

    Key takeaways

    • RNNs process tokens one after another: no parallelism along the sequence, and long paths between distant words.
    • Self-attention connects every pair of tokens in one step and computes all positions in parallel.
    • The price is work that grows with the square of the sequence length.
    • The 2017 paper introduced the recipe; modern LLMs keep its core and change a few details.

    Check yourself

    1. Why can an RNN not be trained in parallel along the sequence?

    Step 50 takes the memory vector produced by step 49 as input, so the steps must run in order.

    2. When does a self-attention layer do less arithmetic than a recurrent layer?

    The costs are T^2 d_{\text{model}} against T\,d_{\text{model}}^2. They are equal at T = d_{\text{model}}.

    3. What was the 2017 paper’s model built for?

    It was an encoder–decoder translation model. Decoder-only language models came afterwards.

    Text to numbers: tokenization and embeddings

    You will be able to

    • Describe an embedding as a row lookup in a learned table.
    • State the shape of the embedding table and of the model’s input.

    Builds on Vectors and matrices; the vocabulary idea from .

    “the cat sat on the” becomes 5 tokens, then 5 integer IDs, then 5 rows of the table E: a matrix of shape [5, d_model]. Both copies of “the” get exactly the same row, which is the problem the next section solves.

    Neural networks do arithmetic, so text has to become numbers. This happens in two steps: the tokenizer cuts text into tokens and replaces each with an integer ID, then the embedding table swaps each ID for a vector of real numbers that the network can learn to adjust.

    Characters, words or subwords?

    • Characters: tiny vocabulary, never meets an unknown symbol, but sequences get very long and each unit carries little meaning.
    • Words: meaningful units, but the vocabulary is enormous and any word not seen in training cannot be represented.
    • Subwords (what real LLMs use): common words stay whole, rare words are assembled from pieces. “played” becomes play + ##ed. Nothing is ever out of vocabulary, and sequences stay short.

    Where the vocabulary comes from. Most GPT-style tokenizers learn it with byte-pair encoding (BPE). Start from single characters, count every adjacent pair in a large sample of text, merge the most frequent pair into one new token, and repeat until the vocabulary reaches the size you want. In the words “low” ×5, “lower” ×2, “newest” ×6 and “widest” ×3, the pairs e s and s t each occur 9 times; merging e s makes es, and then es t is the most frequent pair and becomes est. Frequent words end up as single tokens; rare ones stay in pieces.

    Why do real tokenizers never produce an unknown token?

    Byte-level BPE starts from the 256 possible byte values instead of characters, so any text in any language, emoji and code included, can be written as bytes and therefore as tokens. GPT-2’s vocabulary has 50,257 entries and Llama 3’s about 128,000. The first tokenizer below uses greedy longest-match over a fixed vocabulary, as WordPiece does. The second learns its vocabulary with BPE, merge by merge.

    The equation, and the reasoning behind it

    The question: how should a token be presented to a network that only does arithmetic? Three candidates:

    • The ID itself (say 4071). This would tell the network that token 4071 is nearly the same as 4072 and very different from 12, which is meaningless.
    • A one-hot vector: n_{\text{vocab}} numbers, all 0 except a single 1. No false ordering, but it is enormous and makes every pair of tokens exactly equally different.
    • A short learned vector of d_{\text{model}} numbers per token. Compact, and training can move similar tokens close together. This is the embedding.

    The vectors are stored as the rows of one matrix, and using a token means reading its row:

    x_t = E[w_t], \qquad E\in\mathbb{R}^{n_{\text{vocab}}\times d_{\text{model}}}

    w_t is the token ID at position t. E is the embedding table. E[w_t] is its row number w_t. x_t is the resulting vector of length d_{\text{model}}.

    Math detail: lookup is a matrix product in disguise

    Multiplying a one-hot row vector by E picks out exactly one row: x_t=\mathrm{onehot}(w_t)\,E. Nobody computes it that way because indexing is far cheaper, but it shows that the embedding table is an ordinary weight matrix, trained by gradient descent like every other one.

    Worked example

    Take n_{\text{vocab}}=5 and d_{\text{model}}=2:

    E=\begin{bmatrix}0.1&0.3\\-0.2&0.5\\0.7&-0.4\\0.0&0.9\\0.6&0.6\end{bmatrix},\quad w_t=2 \;\Rightarrow\; \mathrm{onehot}(w_t)=[0,0,1,0,0] \;\Rightarrow\; x_t=E[2]=[0.7,\,-0.4]

    Rows are counted from 0, so ID 2 is the third row.

    Think of the embedding table as a spreadsheet with one row per token. Token ID 2 means “use row 2”. That row of numbers is the token’s vector.

    In Python: a greedy subword tokenizer and the embedding lookup
    Runs on its own · Python 3 + NumPy
    import numpy as np

# A toy WordPiece-style vocabulary. "##" marks a piece that continues a word.
letters = "abcdefghijklmnopqrstuvwxyz"
vocab = (["[UNK]", "the", "cat", "sat", "on", "mat", "play", "jump", "un",
          "##s", "##ed", "##ing", "##happy", "##ly"]
         + list(letters) + ["##" + c for c in letters])
token_id = {tok: i for i, tok in enumerate(vocab)}


def tokenize_word(word):
    """Greedy longest match from the left, as WordPiece does."""
    pieces, start = [], 0
    while start < len(word):
        for end in range(len(word), start, -1):  # try the longest piece first
            piece = word[start:end] if start == 0 else "##" + word[start:end]
            if piece in token_id:
                pieces.append(piece)
                start = end
                break
        else:
            return ["[UNK]"]  # no piece fits, not even one letter
    return pieces


def tokenize(text):
    return [p for word in text.lower().split() for p in tokenize_word(word)]


for text in ["the cats played", "unhappy", "zebra"]:
    toks = tokenize(text)
    print(f"{text!r:18} -> {toks} -> ids {[token_id[t] for t in toks]}")

# Embedding lookup: each ID selects one row of the table E
E = np.array([[0.1, 0.3], [-0.2, 0.5], [0.7, -0.4], [0.0, 0.9], [0.6, 0.6]])
w_t = 2
print("E[2]            =", E[w_t])

one_hot = np.zeros(len(E))
one_hot[w_t] = 1
print("onehot(2) @ E   =", one_hot @ E)  # the same row, by a matrix product

# The model's input: one row per token, shape [T, d_model]
rng = np.random.default_rng(0)
E_big = rng.normal(0, 0.02, size=(len(vocab), 8))  # untrained: random numbers
ids = [token_id[t] for t in tokenize("the cat sat on the mat")]
X = E_big[ids]
print("X.shape         =", X.shape)
print("both 'the' rows equal:", np.array_equal(X[0], X[4]))

    In Python: learn BPE merges and encode new words
    Runs on its own · Python 3, standard library only
    from collections import Counter

# Word counts from the text in this section: "low" 5 times, "lower" twice, and so on
words = {"low": 5, "lower": 2, "newest": 6, "widest": 3}
corpus = {tuple(w): n for w, n in words.items()}   # every word starts as single characters


def count_pairs(corpus):
    pairs = Counter()
    for pieces, n in corpus.items():
        for a, b in zip(pieces, pieces[1:]):
            pairs[a, b] += n
    return pairs


def merge(pieces, pair):
    out, i = [], 0
    while i < len(pieces):
        if pieces[i:i + 2] == pair:
            out.append(pieces[i] + pieces[i + 1])
            i += 2
        else:
            out.append(pieces[i])
            i += 1
    return tuple(out)


merges = []
for step in range(6):
    pairs = count_pairs(corpus)
    best = max(pairs, key=pairs.get)                # ties go to the pair seen first
    merges.append(best)
    corpus = {merge(p, best): n for p, n in corpus.items()}
    print(f"merge {step + 1}: {' + '.join(best):8} ({pairs[best]} times) ->",
          "  ".join(" ".join(p) for p in corpus))


def encode(word):
    """Apply the learned merges, in the order they were learned."""
    pieces = tuple(word)
    for pair in merges:
        pieces = merge(pieces, pair)
    return list(pieces)


for w in ["lowest", "newer", "wider"]:
    print(f"{w:7} -> {encode(w)}")

    What training does to embeddings

    At the start the vectors are random. Training nudges them so that tokens used in similar contexts end up with similar vectors. Real embeddings have hundreds or thousands of dimensions; squashed to two for plotting, related tokens tend to sit near each other.

A sum like king − man + woman takes the offset from man to king and applies it to woman; it lands on queen because the same offset separates both pairs. The last example applies the cat-to-dog offset to man, which means nothing for people: with the inputs included, the nearest token is man itself, and with them left out the “answer” is woman, 1.27 away from the result, where no token sits. Analogies only work where the space has a consistent direction for the relationship.

    Common misconceptions

    • “One token is one word.” A rough rule for English is 3 to 4 characters per token. Rare words, names and code split into many pieces.
    • “Token IDs carry meaning.” ID 6 is not “close to” ID 7. IDs are arbitrary labels; only the embedding vectors carry meaning.
    • “Embeddings are designed by people.” They start random and are learned. Nobody assigns a dimension to mean “is an animal”.
    • Pitfall: a model must be used with the exact tokenizer it was trained with. A different tokenizer produces IDs that point at the wrong rows.

    Key takeaways

    • A tokenizer is a fixed algorithm, not a neural network: text in, integer IDs out.
    • An embedding is a lookup: ID w_t selects row E[w_t].
    • E has shape [n_vocab, d_model] and is learned like any other weight matrix.
    • Training moves tokens that are used alike close together; nobody assigns the dimensions a meaning.

    Builds on Embeddings from ; sine and cosine.

    Each of the 5 vectors gets a position vector added. The two “the” tokens, at positions 0 and 4, started identical and are now different. The shape is still [5, d_model].

    The attention mechanism you will meet next treats its input as an unordered collection of vectors. Shuffle the input tokens and each token’s output is the same as before, just shuffled along with it. So “dog bites man” and “man bites dog” would look identical to it. To fix this, we add a second vector to every token embedding that depends only on where the token sits.

    E[“dog”]what the token is
    +
    position vector for slot 2where it is
    =
    input to layer 1“dog, in third place”

    Two common ways to build position vectors

    • Learned positional embeddings (GPT-2): a second table E_{\text{pos}} with one trainable row per position. Simple, but there is no row for positions beyond the trained maximum.
    • Sinusoidal positional encoding (the original Transformer): a fixed formula using sine and cosine waves of different wavelengths. Nothing to train, and any position has a defined value.

    Many recent models use relative schemes such as rotary embeddings (RoPE) that inject position inside attention itself. The goal is unchanged: make order visible.

    The equations, and the reasoning behind them

    The question: what vector should stand for “position t”? It has to have length d_{\text{model}} so it can be added to a token vector, its values should stay small, every position needs a different vector, and neighbouring positions should get similar ones.

    The idea: think of how a binary counter writes numbers. The last digit flips at every step, the next one every two steps, the next every four. Read together, the digits identify the number. Sinusoidal encoding is the smooth version of this: each pair of dimensions is a wave with its own wavelength, short for the first pairs and very long for the last.

    PE(t,2i)=\sin\!\left(\frac{t}{10000^{2i/d_{\text{model}}}}\right),\qquad PE(t,2i+1)=\cos\!\left(\frac{t}{10000^{2i/d_{\text{model}}}}\right)

    t is the position (0, 1, 2, …); i=0,1,\dots,d_{\text{model}}/2-1 numbers the pairs of dimensions, so dimensions 2i and 2i+1 share a wavelength. The 2017 paper writes pos where this guide writes t.

    Why this form?
    The divisor 10000^{2i/d_{\text{model}}} grows from 1 for the first pair to almost 10000 for the last, so wavelengths run from about 6 positions to about 63,000: fast waves separate neighbours, slow waves separate distant positions. Sine and cosine come as a pair because together they fix a point on a circle, like a clock hand; with sine alone, two positions on either side of a peak would look identical. The constant 10000 is simply large enough that the slowest wave never repeats within a realistic sequence.

    The input to the first layer is the sum of the two vectors. From here on, x_t means this sum:

    x_t = E[w_t] + PE(t)
    Why add and not concatenate?
    Adding keeps the width at d_{\text{model}}, so nothing downstream changes size. In hundreds of dimensions there is room for both signals, and the model learns to read content from some directions and position from others.

    Worked example

    With d_{\text{model}}=4 there are two pairs: i=0 divides by 10000^{0}=1 and i=1 divides by 10000^{2/4}=100.

    \begin{aligned}PE(0)&=[\sin 0,\ \cos 0,\ \sin 0,\ \cos 0]=[0,\ 1,\ 0,\ 1]\\ PE(1)&=[\sin 1,\ \cos 1,\ \sin 0.01,\ \cos 0.01]=[0.8415,\ 0.5403,\ 0.0100,\ 1.0000]\\ PE(2)&=[\sin 2,\ \cos 2,\ \sin 0.02,\ \cos 0.02]=[0.9093,\ -0.4161,\ 0.0200,\ 0.9998]\end{aligned}

    The first two numbers change a lot from one position to the next. The last two barely move; they only become informative across hundreds of positions.

    Picture a row of clock hands turning at different speeds. The fast hands distinguish position 3 from position 4. The slow hands distinguish position 30 from position 300. Read together, they give every position a unique fingerprint.

    In Python: sinusoidal position vectors
    Runs on its own · Python 3 + NumPy
    import numpy as np


def sinusoidal_pe(T, d_model):
    t = np.arange(T)[:, None]                 # positions, shape [T, 1]
    i = np.arange(d_model // 2)[None, :]      # pair index, shape [1, d_model/2]
    angle = t / 10000 ** (2 * i / d_model)    # shape [T, d_model/2]
    pe = np.zeros((T, d_model))
    pe[:, 0::2] = np.sin(angle)               # even dimensions: sine
    pe[:, 1::2] = np.cos(angle)               # odd dimensions: cosine
    return pe


print(sinusoidal_pe(3, 4).round(4))

    Math detail: equivariant, strictly speaking

    People say attention is “permutation-invariant”. The precise statement is that self-attention without positions is permutation-equivariant: permuting the inputs permutes the outputs in the same way and changes nothing else. Anything computed from the collection as a whole is then invariant to order. Either way, word order is invisible.

    This holds for attention with no mask. A causal mask does break the symmetry, because each token sees a different number of predecessors, but that is a weak and indirect signal. GPT-style models still add explicit positional information.

    Common misconceptions

    • “Adding position vectors corrupts the token’s meaning.” In high dimensions there is room for both. The model learns to read content and position from the same vector.
    • “Position is concatenated.” In the classic design it is added, so the vector size stays d_{\text{model}}.
    • Pitfall: a model with learned absolute positions cannot process sequences longer than its position table.

    Key takeaways

    • Attention by itself treats its input as a set, so order must be supplied.
    • Each position gets its own vector of length d_{\text{model}}, added to the token vector.
    • Sinusoidal encoding: fast waves separate neighbours, slow waves separate distant positions.
    • Learned position tables and newer relative schemes do the same job in other ways.

    Builds on The input matrix X from ; dot products; softmax from .

    The token “sat” builds a query. It matches the key of “cat” best, so about 46% of its attention goes there, and its new vector is mostly made of “cat”’s value. (The simulator uses the five words “the cat sat on mat” so that the tables stay small.)

    So far each token’s vector knows only about itself. To predict what follows “The cat sat on the”, the vector for “the” needs information from “cat” and “sat”. Self-attention is the step where every token gathers information from the other tokens, deciding for itself which ones matter.

    Queries, keys and values: a library analogy

    Imagine each token is both a reader and a book in a library.

    • As a reader it writes a query: a note describing what it is looking for.
    • As a book it carries a key: a label on the spine describing what it contains.
    • It also holds a value: the content it hands over if someone picks it.

    Each reader compares its query with every book’s key. A good match means “read more of this one”. But instead of choosing a single book, the reader takes a blend of all the values, weighted by how well each key matched.

    query qwhat am I looking for?
    ·
    keys k₁ … kₙwhat does each token offer?
    →
    scoresone dot product per token
    →
    softmaxweights that sum to 1
    →
    blend of valuesweighted sum of v₁ … vₙ

    Deriving the formula, one decision at a time

    The goal: give token i a new vector that summarises the other tokens, weighted by how relevant each is to token i. Each step below settles one design question. The input is the matrix X of shape [T, d_model], whose row t is the vector x_t from the previous section.

    1. Three roles, three projections. What a token is looking for, what it advertises about itself, and what it hands over are three different things. So each gets its own learned matrix:

    Q = XW_Q,\qquad K = XW_K,\qquad V = XW_V

    Row i of Q is the query q_i; row j of K and V are the key k_j and value v_j. Each matrix has shape [T, d_k], where d_k is the length of a query or key.

    2. Relevance is a dot product. We need one number for “how relevant is token j to token i?”. The dot product q_i\cdot k_j is large when the two vectors point the same way, near zero when they are unrelated and negative when they are opposed. It is cheap, and because W_Q and W_K are learned, the model itself decides what “pointing the same way” should mean.

    3. Divide by \sqrt{d_k}. A dot product adds up d_k terms, so longer vectors give larger scores for no meaningful reason. If each term varies by about 1, the sum varies by about \sqrt{d_k}. Dividing by \sqrt{d_k} brings the scores back to a typical size of about 1, whatever d_k is.

    Why do large scores hurt?
    With large scores, softmax gives almost all the weight to one token. Its output then hardly changes when the scores change a little, so the gradients that training relies on become tiny, and learning stalls.

    4. Softmax turns scores into a budget. Token i should distribute a fixed amount of attention: weights that are positive and sum to 1. That is exactly what softmax produces ().

    5. Blend the values. The new vector is the average of the value vectors, weighted by the budget.

    s_{ij}=\frac{q_i\cdot k_j}{\sqrt{d_k}},\qquad \alpha_{ij}=\frac{e^{s_{ij}}}{\sum_{j'}e^{s_{ij'}}},\qquad c_i=\sum_j \alpha_{ij}\,v_j

    s_{ij} is the scaled score of key j for query i. \alpha_{ij} is the attention weight. c_i is the context vector for token i.

    6. All tokens at once. The same steps, written with matrices, handle every token in one go. Entry (i,j) of QK^{\top} is q_i\cdot k_j. Softmax is applied to each row. Multiplying by V then forms every weighted sum:

    \mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
    • Q, K, V: one row per token, shape [T, d_k].
    • QK^{\top}: every query dotted with every key, shape [T, T].
    • softmax, applied to each row: one query’s scores become weights that sum to 1.
    • Multiplying by V: row i of the result is c_i. Output shape [T, d_k].

    Take d_k=4, the query q_{\text{sat}}=[1,2,0,0] and the keys and values shown in the simulator below.

    \begin{aligned}\text{dot products } q\cdot k_j &= [1,\ 4,\ 3,\ 0,\ 1]\\ \text{divide by }\sqrt{4}=2 &\Rightarrow [0.5,\ 2,\ 1.5,\ 0,\ 0.5]\\ \exp &\Rightarrow [1.6487,\ 7.3891,\ 4.4817,\ 1,\ 1.6487],\ \text{sum}=16.1682\\ \alpha &= [0.1020,\ 0.4570,\ 0.2772,\ 0.0618,\ 0.1020]\\ c=\textstyle\sum_j\alpha_jv_j &= [0.7119,\ 1.1912,\ 0.4410,\ 0.3276]\end{aligned}

      The whole attention matrix, and the causal mask

      Running every token as a query gives a square table: row i shows where token i looks. A GPT-style model has one more rule.       s_{ij}\leftarrow\begin{cases}s_{ij}& j\le i\\-\infty& j\gt i\end{cases}\qquad\text{then}\qquad \alpha_{i}=\mathrm{softmax}(s_{i})

def softmax(S, axis=-1):
    e = np.exp(S - S.max(axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)


def attention(Q, K, V, causal=False):
    d_k = Q.shape[-1]
    S = Q @ K.T / np.sqrt(d_k)                      # [T, T] scores
    if causal:
        T = S.shape[0]
        future = np.triu(np.ones((T, T), dtype=bool), k=1)  # j > i
        S = np.where(future, -np.inf, S)            # mask BEFORE softmax
    A = softmax(S)                                  # each row sums to 1
    return A @ V, A

      Common misconceptions

      • “Attention weights explain the model’s reasoning.” They show where information flowed in one layer and head. They are a useful clue, not a complete explanation.
      • “The mask is applied after softmax.” It must be applied before, so the remaining weights still sum to 1.
      • “Q, K and V are three different inputs.” In self-attention all three are projections of the same token vectors.
      • Pitfall: forgetting the \sqrt{d_k} scaling. With large d_k, unscaled scores make softmax nearly one-hot and learning stalls.

      Key takeaways

      • Attention = for each token, a weighted average of all tokens’ value vectors.
      • Weights come from query·key dot products, scaled by \sqrt{d_k}, then softmax.
      • In matrix form: \mathrm{softmax}(QK^{\top}/\sqrt{d_k})\,V.
      • The causal mask sets scores for later tokens to −∞ so that a position cannot see the future.
      • Attention weights show where information was read from; they are not an explanation of the model’s reasoning.

      Builds on The single-head formula from .

      One head could link “sat” to its subject “cat”, while another links each word to the word before it. The widget below uses a longer sentence, “the cat sat because it purred”, so that a third head can link “it” back to “cat”.

      A single attention computation gives each token one set of weights, so it can ask only one kind of question at a time. But a token often needs several things at once: the previous word, the subject of the sentence, what “it” refers to.

      Multi-head attention runs several smaller attention computations side by side, each with its own learned projections, and joins the results.

      X[B, T, d_model]
      →
      head 1 … head heach: own W_Q, W_K, W_V of width d_{\text{model}} / h
      →
      h outputseach [B, T, d_model / h]
      →
      Concat[B, T, d_model]
      →
      W_Omix the heads

      The equations, and the reasoning behind them

      Run h separate attention computations, called heads. Each head works in a smaller space of d_k=d_{\text{model}}/h dimensions, so all of them together cost about the same as one full-width head. Each has its own projection matrices of shape [d_model, d_k]:

      \mathrm{head}_m=\mathrm{Attention}\!\left(XW_Q^{(m)},\;XW_K^{(m)},\;XW_V^{(m)}\right),\qquad m=1,\dots,h

      This is the single-head formula from , with matrices that belong to head m. The superscript (m) only says “which head”. Each head’s output has shape [T, d_k]. The 2017 paper writes these matrices as W_i^{Q}, W_i^{K}, W_i^{V}.

      The h outputs are placed side by side, which restores the width h\cdot d_k=d_{\text{model}}, and one more matrix mixes them:

      \mathrm{MultiHead}(X)=\mathrm{Concat}(\mathrm{head}_1,\dots,\mathrm{head}_h)\,W_O
      Why W_O?
      Concatenation alone would confine each head to its own fixed slice of the output vector. The matrix W_O, of shape [d_model, d_model], lets the model combine what different heads found and write the result anywhere in the vector that later layers read. In code the per-head projections are usually one big matrix whose output is reshaped into h slices, which is the same thing.
      TensorShapeMeaning
      Input X[B, T, d_model]one vector per token, for each of B sequences
      Q, K, V after projecting and splitting[B, h, T, d_k]one set per head, with d_k = d_{\text{model}} / h
      Scores, and weights after softmax[B, h, T, T]one T × T table per head
      Each head’s output[B, h, T, d_k]weights times values
      After concatenation, and after W_O[B, T, d_model]same shape as the input

      Worked example

      With d_{\text{model}}=8 and h=2, each head works with d_k=4. Head 1 produces 4 numbers per token, head 2 another 4; concatenated they give 8 again. Parameters for the query, key and value projections: one head needs 3\times(8\times8)=192 weights; two heads need 2\times3\times(8\times4)=192. The same.

      Splitting an 8-number vector between 2 heads gives each head 4 numbers to work with. You get two independent “where should I look?” decisions for the price of one.

      Common misconceptions

      The feed-forward network (MLP)

      Why it is needed. Attention mostly averages: each output is a weighted sum of value vectors. Something has to transform what was gathered.

      After attention has gathered context, each token’s vector is passed through the same small network, independently of every other token. Attention decides what to collect; the MLP decides what to make of it. Most of a Transformer’s parameters live here. It works in three moves:

      • Expand. W_1 maps the vector from d_{\text{model}} up to d_{\text{ff}} numbers, typically 4 times as many. Think of each of these as a detector for one pattern.
      • Bend. A non-linear function lets each detector respond strongly to some inputs and stay quiet for others.
      • Contract. W_2 maps back to d_{\text{model}}, writing what the detectors found into the token’s vector.
      \mathrm{FFN}(x)=\mathrm{GELU}(xW_1+b_1)\,W_2+b_2

      x is one token’s vector, of length d_{\text{model}}. W_1 has shape [d_model, d_ff] and W_2 has shape [d_ff, d_model]. b_1 and b_2 are bias vectors.

      Why the non-linearity?
      Without it the formula would be (xW_1)W_2=x(W_1W_2): two matrices in a row are just one matrix, so the second layer would add nothing. The bend in the middle is what lets the network compute things a single matrix cannot. A note on notation: many texts write this as W_2\,\mathrm{GELU}(W_1x+b_1)+b_2 with column vectors. It is the same computation transposed. This guide writes vectors as rows, so xW lines up with the shapes [T, d_model] you see in code.

      This guide uses GELU, the activation in GPT-2 and GPT-3. Many newer models use a gated variant, SwiGLU (see ). GELU is applied to each number a separately:

      \mathrm{GELU}(a)=a\,\Phi(a),\qquad \mathrm{ReLU}(a)=\max(0,a)

      \Phi(a) is the probability that a standard normal random number is below a, a value between 0 and 1.

      Why this form?
      Read \Phi(a) as a smooth gate: close to 1 for large positive a (the input passes through), close to 0 for large negative a (it is blocked), and in between near zero. ReLU is the same gate with a hard on/off switch at 0. The smooth version gives a usable gradient everywhere, which tends to make training better behaved.

      Worked example: a tiny FFN

      Input x=[1,2], d_{\text{ff}}=3, biases zero.

      W_1=\begin{bmatrix}1&0.5&-1\\-1&2&1\end{bmatrix},\quad xW_1=[-1,\ 4.5,\ 1],\quad \mathrm{GELU}=[-0.1587,\ 4.5000,\ 0.8413]
      W_2=\begin{bmatrix}1&0\\0&1\\1&-1\end{bmatrix},\quad \mathrm{FFN}(x)=[0.6827,\ 3.6586]

      The first entry of xW_1 is 1\cdot1+2\cdot(-1)=-1. The first output is -0.1587+0.8413 and the second is 4.5000-0.8413. Results are computed at full precision and rounded for display, which is why a last digit can differ by one from adding the rounded terms.

      The two input numbers are stretched into three, bent by GELU (big positives pass through, negatives are mostly squashed), then recombined into two. The bending is what lets the network compute things a single matrix cannot.

def gelu(a):
    # a * Phi(a), where Phi is the standard normal CDF
    return a * 0.5 * (1 + np.vectorize(math.erf)(a / math.sqrt(2)))


def relu(a):
    return np.maximum(0, a)


def ffn(x, W1, b1, W2, b2):

      Residual connections

      Why they are needed. A stack of dozens of layers is hard to train. As a signal passes through layer after layer, it can fade away or blow up, and so can the gradient on its way back.

      The fix is simple. Instead of replacing a token’s vector, each sublayer adds its result to it:

      x \leftarrow x + \mathrm{Sublayer}(x)

      \mathrm{Sublayer} stands for either attention or the MLP; the arrow means “the new value of x is”.

      Each token’s vector becomes a running total that every layer reads from and writes to. This running total is called the residual stream.

      Why add?
      Two reasons. Going forward, a layer only has to learn a correction to the vector; if it has nothing useful to say it can output something near zero and the information passes through untouched. Going backward, the slope of x+\mathrm{Sublayer}(x) with respect to x is “1 plus the sublayer’s slope”. That constant 1 gives the gradient a path to every earlier layer that is never multiplied by any weights, so it cannot shrink to nothing however deep the stack is.

      Layer normalization

      Why it is needed. As vectors pass through many layers, their scale can drift: they grow huge or shrink towards zero. LayerNorm resets the scale, one token’s vector at a time, in four steps:

      1. Compute the mean of the vector’s numbers: \mu=\frac{1}{d_{\text{model}}}\sum_i x_i.
      2. Compute their variance: \sigma^2=\frac{1}{d_{\text{model}}}\sum_i (x_i-\mu)^2.
      3. Subtract the mean and divide by the standard deviation. The vector now has mean 0 and standard deviation 1.
      4. Multiply by a learned scale \gamma and add a learned shift \beta.
      \mathrm{LayerNorm}(x)=\gamma\odot\frac{x-\mu}{\sqrt{\sigma^{2}+\epsilon}}+\beta

      x_i is the i-th number of the vector. \gamma and \beta are learned vectors of length d_{\text{model}}. \odot multiplies element by element. \epsilon is a tiny constant that prevents division by zero.

      Why step 4?
      Forcing every vector to mean 0 and spread 1 might be too rigid for what a layer needs. \gamma and \beta start at 1 and 0 (no effect) and let training choose a different scale and offset per dimension. The scale is then under the model’s control instead of drifting.

      Worked example: LayerNorm

      x=[2,4,6,8], with \gamma=1,\ \beta=0 and ignoring \epsilon.

      Mean \mu=\tfrac{2+4+6+8}{4}=5. Variance \sigma^2=\tfrac{9+1+1+9}{4}=5, so \sigma=2.2361.

      \mathrm{LayerNorm}(x)=\left[\tfrac{-3}{2.2361},\tfrac{-1}{2.2361},\tfrac{1}{2.2361},\tfrac{3}{2.2361}\right]=[-1.3416,\ -0.4472,\ 0.4472,\ 1.3416]

      Subtract the average so the numbers centre on zero, then divide by their spread. [2, 4, 6, 8] and [200, 400, 600, 800] come out identical: only the pattern survives, not the scale.

def layer_norm(x, gamma=1.0, beta=0.0, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)          # 1. mean
    var = x.var(axis=-1, keepdims=True)          # 2. variance
    x_hat = (x - mu) / np.sqrt(var + eps)        # 3. normalise
    return gamma * x_hat + beta                  # 4. learned scale and shift

      Putting it together: the Transformer block

      GPT-style models use the “pre-norm” arrangement. Read each line below as: normalise a copy of the stream, compute an update from it, add the update to the stream.

      \begin{aligned}x' &= x + \mathrm{MultiHead}(\mathrm{LayerNorm}(x))\\ y &= x' + \mathrm{FFN}(\mathrm{LayerNorm}(x'))\end{aligned}

      x is the block’s input, x' the stream after the attention update and y the block’s output. \mathrm{MultiHead} is the self-attention of , with the causal mask.

      The shape never changes, which is what makes blocks stackable. Tensor shapes are written [batch, sequence_length, d_model], shortened to [B, T, d_model]: B independent sequences processed together, T tokens in each, d_model numbers per token.

import numpy as np


def softmax(S, axis=-1):
    e = np.exp(S - S.max(axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)


def layer_norm(x, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)
    return (x - mu) / np.sqrt(x.var(axis=-1, keepdims=True) + eps)


def gelu(a):
    return a * 0.5 * (1 + np.vectorize(math.erf)(a / math.sqrt(2)))


def multi_head(x, p, h):
    T, d_model = x.shape
    d_k = d_model // h
    split = lambda M: M.reshape(T, h, d_k).transpose(1, 0, 2)  # [h, T, d_k]
    Q, K, V = split(x @ p["W_Q"]), split(x @ p["W_K"]), split(x @ p["W_V"])
    S = Q @ K.transpose(0, 2, 1) / np.sqrt(d_k)
    S = np.where(np.triu(np.ones((T, T), dtype=bool), k=1), -np.inf, S)
    heads = softmax(S) @ V
    return heads.transpose(1, 0, 2).reshape(T, d_model) @ p["W_O"]


def ffn(x, p):
    return gelu(x @ p["W1"]) @ p["W2"]


def block(x, p, h=2):
    x = x + multi_head(layer_norm(x), p, h)   # x' = x + MultiHead(LN(x))
    x = x + ffn(layer_norm(x), p)             # y  = x' + FFN(LN(x'))
    return x

      Common misconceptions

      • “The MLP mixes information between tokens.” It does not. It is applied to each position separately; only attention moves information across positions.
      • “LayerNorm is the same as BatchNorm.” LayerNorm uses statistics of a single token’s vector, so it behaves identically in training and inference and does not depend on batch size.
      • “Residual connections are an optimisation trick you could drop.” Deep Transformers do not train without them.
      • Pitfall: the original 2017 paper put the normalisation after the residual add (post-norm). Pre-norm, shown here, is what GPT-style models use because it is easier to train at depth. compares the two.

      Key takeaways

      • FFN: expand to d_{\text{ff}}, apply GELU, contract back. Applied to each token separately.
      • Residual: every sublayer adds to the stream and never replaces it.
      • LayerNorm: rescale each token’s vector to mean 0, spread 1, then apply a learned scale and shift.
      • Block = x+\mathrm{MultiHead}(\mathrm{LayerNorm}(x)), then the same pattern with the FFN.
      • Input and output shapes match, so blocks stack.

      Builds on Everything from .

      After L blocks, the vector at the last position (the second “the”) is multiplied by W_U to give one logit per vocabulary entry. Softmax turns those into probabilities: “mat” 0.44, “sofa” 0.24, and so on.

      You now have every part. A GPT-style model is those parts in a straight line: turn text into vectors, refine the vectors through a stack of identical blocks, then turn the final vectors back into a probability for every token in the vocabulary. It is called “decoder-only” because it keeps just the generating half of the original encoder–decoder Transformer, which covers.

      The whole model is four lines. Each one is something you have already met:

      \begin{aligned}x^{(0)}_t &= E[w_t]+E_{\text{pos}}[t] &&\text{token and position vectors, added}\\ x^{(\ell)} &= \mathrm{Block}_{\ell}\!\left(x^{(\ell-1)}\right),\ \ \ell=1,\dots,L &&L\text{ blocks, each refining the stream}\\ z &= \mathrm{LayerNorm}\!\left(x^{(L)}\right)W_U &&\text{final normalisation, then vocabulary scores}\\ p &= \mathrm{softmax}(z) &&\text{scores to probabilities}\end{aligned}

      The superscript (\ell) counts blocks: x^{(0)} is the input to the first block and x^{(L)} the output of the last. E_{\text{pos}} is the learned position table (or the sinusoidal PE of ). W_U has shape [d_model, n_vocab], so z holds one logit per vocabulary entry.

      Why does W_U look like that?
      Each logit is the dot product of the final vector with one column of W_U, so there is one column per vocabulary entry, and the entry whose column best matches the vector scores highest. It is the embedding lookup run in reverse, from vector back to token, which is why many models reuse the embedding table E for it (“weight tying”).

      One detail makes training efficient: the model produces a next-token prediction at every position at once. Position 3’s output predicts token 4, and thanks to the causal mask it was computed without seeing token 4.

def gpt_forward(ids, params, h=2):
    T = len(ids)
    x = params["E"][ids] + params["E_pos"][:T]  # x(0) = E[w_t] + E_pos[t]
    for p in params["blocks"]:                  # x(l) = Block_l(x(l-1))
        x = block(x, p, h)
    z = layer_norm(x) @ params["W_U"]           # z = LayerNorm(x(L)) W_U
    return softmax(z)                           # p = softmax(z)

        Counting parameters

        The rule: a linear layer from a numbers to b numbers has a\times b weights and b biases. Apply that to every part of the model:

        • Token embeddings: one row of d_{\text{model}} numbers for each of n_{\text{vocab}} entries.
        • Position embeddings: one row for each of T positions.
        • Attention, per block: four [d_model, d_model] matrices (W_Q, W_K, W_V, W_O), each with a bias of length d_{\text{model}}.
        • MLP, per block: W_1 with its bias (d_{\text{model}}d_{\text{ff}}+d_{\text{ff}}) and W_2 with its bias (d_{\text{ff}}d_{\text{model}}+d_{\text{model}}).
        • LayerNorm: \gamma and \beta, so 2d_{\text{model}} each time; two per block, plus the final one.
        • Output projection: d_{\text{model}}\times n_{\text{vocab}}, or nothing extra if it is shared with the embeddings.
        \underbrace{n_{\text{vocab}}d_{\text{model}}}_{\text{token emb.}}+\underbrace{T\,d_{\text{model}}}_{\text{position emb.}}+L\Big(\underbrace{4(d_{\text{model}}^{2}+d_{\text{model}})}_{\text{attention}}+\underbrace{2\,d_{\text{model}}d_{\text{ff}}+d_{\text{ff}}+d_{\text{model}}}_{\text{MLP}}+\underbrace{4d_{\text{model}}}_{\text{2 LayerNorms}}\Big)+\underbrace{2d_{\text{model}}}_{\text{final LayerNorm}}+\underbrace{n_{\text{vocab}}d_{\text{model}}}_{\text{output proj.}}

        L is the number of blocks, T the context length, d_{\text{ff}} the MLP’s hidden width. The number of heads h does not appear: heads slice the same matrices.

        Worked example

        n_{\text{vocab}}=50,\ d_{\text{model}}=8,\ T=16,\ L=1,\ d_{\text{ff}}=32, output projection not shared:

        Token embeddings 50\times8=400. Position embeddings 16\times8=128. Attention 4\times(64+8)=288. MLP 2\times8\times32+32+8=552. Block LayerNorms 4\times8=32. Final LayerNorm 16. Output projection 400.

        Total: 400+128+288+552+32+16+400=1816 parameters.

        Two kinds of term dominate. Embeddings grow with vocabulary size × width. The blocks grow with layers × width². Doubling the width roughly quadruples the cost of the blocks.

        def count_params(n_vocab, d_model, T, L, d_ff, tied=False):
    token_emb = n_vocab * d_model
    pos_emb = T * d_model
    attention = 4 * (d_model * d_model + d_model)          # W_Q, W_K, W_V, W_O
    mlp = d_model * d_ff + d_ff + d_ff * d_model + d_model  # W1, b1, W2, b2
    block_norms = 2 * 2 * d_model                           # two LayerNorms
    final_norm = 2 * d_model
    output = 0 if tied else d_model * n_vocab
    total = token_emb + pos_emb + L * (attention + mlp + block_norms) \
        + final_norm + output
    return {"token emb": token_emb, "position emb": pos_emb,
            "blocks": L * (attention + mlp + block_norms),
            "final norm": final_norm, "output": output, "total": total}

        How the total scales with width
        Counts assume learned position embeddings and biases on every linear layer, as in GPT-2. The GPT-2 presets use that model family’s published sizes. Architectures that differ in these details will be off by a small percentage.
        What just happened? Changing the number of heads changed nothing: heads split the same matrices into slices. Changing d_{\text{model}} changed almost everything, because attention and MLP weights are both proportional to its square. More parameters means more memory to hold them and more arithmetic for every token processed, in both training and inference.

        Common misconceptions

        • “Longer context means more parameters.” Barely: only the position table grows. What grows is compute, since attention compares every token with every other one, giving O(T^2) work per layer.
        • “The model only predicts at the last position.” It predicts at every position. Training uses all of them; generation reads only the last.
        • “Decoder-only means something is missing.” It is a complete design. The prompt and the output simply share one sequence.
        • Pitfall: memory for weights is the floor, not the total. Activations, the KV cache and, in training, gradients and optimizer state all add to it.

        Key takeaways

        • Model = embeddings + positions → L blocks → final LayerNorm → W_U → softmax.
        • The stream keeps the shape [B, T, d_model] until the output projection makes it [B, T, n_vocab].
        • Every position produces a prediction for its own next token, all in one pass.
        • Parameters: embeddings grow with n_{\text{vocab}}\cdot d_{\text{model}}; blocks grow with L\cdot d_{\text{model}}^{2}.

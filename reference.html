The maths you need

The guide assumes programming and the ideas on this page, nothing more. If any of them feel rusty, spend about 15 minutes here first. Each idea comes with one example you can check by hand, and links to where the guide uses it.

Vectors and the dot product

A vector is a list of numbers. In this guide every token becomes a vector, and vectors are written as rows. The dot product of two vectors of the same length multiplies them position by position and adds the results:

q\cdot k=q_1k_1+q_2k_2+\dots+q_nk_n

Example. [1,2,0]\cdot[2,1,3]=1\cdot2+2\cdot1+0\cdot3=4, while [1,2,0]\cdot[-1,0,2]=-1. The result is large when two vectors point the same way, near zero when they are unrelated, and negative when they point in opposite directions.

Where it appears: (tokens as vectors) and (scores between tokens).

Matrix multiplication and shapes

A matrix is a table of numbers. Multiplying a row vector by a matrix takes the dot product of the vector with each column of the matrix, so it turns a vector of one length into a vector of another. This is what a layer in a neural network does.

x=[1,\ 2],\qquad W=\begin{bmatrix}1&0&1\\0&1&1\end{bmatrix}
xW=[1,\ 2,\ 3]

The third entry, for example, is 1\cdot1+2\cdot1=3. Shapes follow one rule: the inner sizes must match, and they disappear. A [1, 2] vector times a [2, 3] matrix gives [1, 3]. Stack T token vectors as rows and the same rule gives [T, d_model] times [d_model, d_k] equals [T, d_k]. W^{\top}, the transpose, swaps rows and columns.

Exponentials and logarithms

e\approx2.718. The exponential e^a is always positive and grows quickly: e^0=1, e^1\approx2.718, e^2\approx7.389, e^{-2}\approx0.135. The natural logarithm \log undoes it: \log e^a=a. It turns products into sums, \log(ab)=\log a+\log b.

The guide mostly takes logarithms of probabilities, which lie between 0 and 1, so the results are 0 or negative. Minus the log of a probability measures surprise:

Probability p10.90.50.01
-\log p00.1050.6934.605

A sure prediction costs nothing; a confident wrong one costs a lot.

Where it appears: the loss in , which is exactly this surprise, averaged over tokens.

Softmax: from scores to probabilities

Softmax turns any list of scores into probabilities: positive numbers that add up to 1. Take e to the power of each score, then divide each result by their sum:

\operatorname{softmax}(z)_i=\frac{e^{z_i}}{\sum_j e^{z_j}}

Example. Scores [2,1,0] give [7.389,\ 2.718,\ 1], which add up to 11.107. Dividing gives [0.665,\ 0.245,\ 0.090]. The largest score gets the largest share, but every option keeps some probability.

Where it appears: (next-token probabilities), (attention weights) and (temperature).

Averages, variance and standard deviation

The mean is the average. The variance is the average squared distance from the mean, and the standard deviation is its square root: a typical distance from the mean.

Example. For [1,2,3,6] the mean is 12/4=3. The distances from it are -2,-1,0,3, whose squares add up to 14, so the variance is 14/4=3.5 and the standard deviation is \sqrt{3.5}\approx1.871.

Slopes, gradients and gradient descent

The derivative of a function is its slope: how much the output changes when the input moves a little. A model has millions of parameters, and the gradient is the list of slopes of the loss, one for each parameter. Training repeatedly takes a small step downhill:

w\leftarrow w-\eta\times\text{slope}

Example. Take the loss (w-3)^2, which is lowest at w=3. Its slope is 2(w-3), so at w=1 the slope is -4. With a learning rate \eta=0.1, the step gives w=1-0.1\times(-4)=1.4, and the loss falls from 4 to 2.56. You never compute gradients by hand in this guide; libraries do it. You only need the idea.

Large numbers and memory

Model sizes are written in powers of ten: 7 billion is 7\times10^9. A gigabyte (GB) is 10^9 bytes. To find memory, multiply a count by the bytes each item takes.

Example. A 7-billion-parameter model at 2 bytes per parameter takes 7\times10^9\times2=1.4\times10^{10} bytes, which is 14 GB.

Glossary

Byte-pair encoding (BPE)
The usual way to learn a subword vocabulary: start from characters or bytes and repeatedly merge the most frequent adjacent pair into a new token.
Token
The unit of text a model reads and writes: a word, part of a word, a character or a symbol.
Embedding
A learned vector that represents a token (or a position) as numbers the network can compute with.
Attention
The operation that lets each token build a weighted blend of information from other tokens.
Query
The vector a token uses to express what it is looking for in other tokens.
Key
The vector a token exposes so queries can be matched against it.
Value
The vector a token contributes to whoever attends to it.
Softmax
A function that turns any list of numbers into positive values that sum to 1.
Logits
The raw, unnormalised scores a model outputs, one per vocabulary entry.
Logits vs. probabilities
Logits can be any real number and only their differences matter; probabilities are what softmax makes of them, lying between 0 and 1 and summing to 1.
Residual stream
The running vector for each token that every layer reads from and adds to.
LayerNorm
Rescales one token’s vector to mean 0 and standard deviation 1, then applies a learned scale and shift.
MLP
Multi-layer perceptron: the feed-forward network applied to each token separately inside every block.
Context window
The maximum number of tokens the model can take as input at once.
KV cache
Stored keys and values of earlier tokens, reused during generation to avoid recomputing them.
Temperature
A divisor applied to logits before softmax; low values sharpen the distribution, high values flatten it.
Top-k
Sampling restricted to the k most probable tokens.
Top-p
Sampling restricted to the smallest set of top tokens whose probabilities total at least p. Also called nucleus sampling.
Loss
A single number measuring how wrong the model’s predictions were; training tries to lower it.
Gradient
For every parameter, the rate at which the loss changes when that parameter changes.
Optimizer
The algorithm that converts gradients into parameter updates, for example SGD or AdamW.
Parameter
One learned number in the model: an entry of a weight matrix, bias or embedding.
Checkpoint
A saved snapshot of all parameters (and often optimizer state) at some point in training.
Fine-tuning
Further training of a pretrained model on a smaller, more specific dataset.
Base model
A model after pretraining only: it continues text rather than following instructions.
Chat template
The special tokens and layout that turn a list of messages into the single sequence a chat model was trained on.
Reasoning model
A model trained with reinforcement learning on checkable tasks to write out intermediate steps before answering; better on hard problems, slower and costlier per answer.
RLHF
Reinforcement learning from human feedback: optimising a model towards outputs people prefer.
Encoder
A Transformer stack with unmasked self-attention that reads a whole input sequence and outputs one vector per token.
Decoder
A Transformer stack with causal self-attention that generates a sequence one token at a time.
Cross-attention
Attention whose queries come from the decoder and whose keys and values come from the encoder output.
Prefill
The first phase of inference: the whole prompt is processed in one parallel pass and its keys and values are cached.
Time to first token
The delay between sending a request and receiving the first output token; roughly the prefill time.
Throughput
Tokens generated per second summed over all requests being served at once.
BLEU
A 0 to 100 score for machine translation that measures overlap of word sequences with human reference translations.
Warm-up
Raising the learning rate gradually from near zero over the first training steps, before letting it decay.
Hallucination
Fluent output that is false or unsupported. It arises because the model generates probable text, not verified facts.
RAG
Retrieval-augmented generation: fetching relevant passages at query time and placing them in the prompt so the model answers from them.
Embedding model
A model that maps a whole text to one vector so that similar texts have similar vectors; used for semantic search.
Cosine similarity
The dot product of two vectors after scaling each to length 1; the usual similarity measure for embeddings.
BM25
A classic keyword-ranking formula; strong for exact terms such as names and codes.
Reranker
A model that reads a query and a passage together and scores their relevance; more accurate and slower than embedding search.
HNSW
Hierarchical navigable small world: a graph index for fast approximate nearest-neighbour search.
Chunking
Splitting documents into passages of manageable size before embedding them.
SFT
Supervised fine-tuning on prompt and ideal-response pairs.
LoRA
Low-rank adaptation: fine-tuning by learning a small low-rank update to frozen weight matrices.
QLoRA
LoRA trained on top of a base model stored in 4-bit precision.
DPO
Direct preference optimization: training on chosen and rejected answer pairs without a separate reward model.
Reward model
A model trained to predict which of two responses people prefer; used in RLHF.
Distillation
Training a smaller model to imitate a larger one.
Agent
An LLM running in a loop that chooses actions, such as tool calls, until a goal is reached.
Tool calling
The model emits a structured request (name and arguments) for your code to run a function and return the result.
Human-in-the-loop
Pausing an agent so a person can approve, edit or reject a step before it continues.
LangChain
An open-source framework with integrations for many model providers and tools, and agent building blocks such as create_agent; its agents are built on LangGraph.
LangGraph
A low-level runtime for long-running, stateful agents: the flow is a graph of nodes and edges over shared state, with checkpoints, streaming and pauses for human input.
Prompt injection
Instructions hidden in user input, documents or tool output that try to override the intended behaviour.
LLM-as-judge
Using a language model with a rubric to score or compare outputs.
Perplexity
The exponential of the cross-entropy loss: the effective number of choices the model is unsure between.
RoPE
Rotary position embedding: encodes position by rotating query and key vectors.
RMSNorm
LayerNorm without the mean subtraction and the shift: divides a vector by its root mean square, then applies a learned gain.
SwiGLU
A gated feed-forward network: one projection, passed through SiLU, multiplies another element by element.
GQA
Grouped-query attention: several query heads share one key/value head, shrinking the KV cache.
FlashAttention
An exact attention algorithm that works tile by tile in fast memory, avoiding the full T × T matrix.
Mixture of experts
A layer with many expert MLPs and a router that sends each token to only a few of them.
Quantization
Storing weights (and sometimes activations or the KV cache) in fewer bits to save memory and bandwidth.
Speculative decoding
A small draft model proposes tokens that the large model verifies in one pass, speeding up generation.
GPU
A processor with thousands of simple cores that apply the same operation to many numbers at once; it runs nearly all model training and inference.
Tensor core
A unit inside a GPU that multiplies a small block of a matrix in one step, at reduced precision such as bf16 or fp8.
VRAM
The GPU’s own memory. The weights, the KV cache and intermediate values must fit in it.
Memory bandwidth
The bytes per second a GPU can read from its memory; the usual limit on generation speed for a single request.
CUDA
NVIDIA’s platform for running programs on its GPUs: a driver, a runtime, a compiler and libraries such as cuBLAS and cuDNN.
bf16
A 16-bit floating-point format with the same range as 32-bit floats and less precision; the usual format for training and inference.
Open-weight model
A model whose trained weights anyone can download and run. Not the same as open source: the training data and code are usually not published, and a licence sets the terms of use.
Ollama
An app for Windows, macOS and Linux that downloads quantized open-weight models by name and runs them on a GPU, a CPU or both, with an OpenAI-compatible API.
vLLM
A serving engine for Linux GPU servers that handles many requests at once with continuous batching and paged KV-cache memory, with an OpenAI-compatible API.
GGUF
The single-file model format used by llama.cpp and Ollama, usually holding quantized weights.

Further learning

Foundational papers

  • Attention Is All You Need, Vaswani et al., 2017. The paper that introduced the Transformer.
  • Layer Normalization, Ba, Kiros and Hinton, 2016.
  • Gaussian Error Linear Units (GELUs), Hendrycks and Gimpel, 2016.
  • Adam: A Method for Stochastic Optimization, Kingma and Ba, 2014.
  • Scaling Laws for Neural Language Models, Kaplan et al., 2020.
  • Training Compute-Optimal Large Language Models, Hoffmann et al., 2022.
  • Training language models to follow instructions with human feedback, Ouyang et al., 2022.

Resources for going deeper

  • The Illustrated Transformer, Jay Alammar. A gentle visual walkthrough.
  • The Annotated Transformer, Harvard NLP. The original paper, line by line, in PyTorch.
  • nanoGPT, Andrej Karpathy. A small, readable GPT training codebase; his “Let’s build GPT” video builds one from an empty file.
  • A Mathematical Framework for Transformer Circuits, Elhage et al., 2021. Where the “residual stream” view comes from.

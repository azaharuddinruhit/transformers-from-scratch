    Builds on Self-attention and the causal mask from ; the block from .

    A different task for this section: translating “le chat noir dort”. To write “black”, the decoder queries the encoder’s output and puts 61% of its attention on “noir”.

    Everything so far described a single stack that reads and writes one sequence. The original 2017 Transformer was built differently, for translation: one stack, the encoder, reads the whole input sentence; a second stack, the decoder, writes the output sentence one token at a time. The two are joined by a third kind of attention, cross-attention, through which the decoder consults the encoder’s result at every step.

    • Encoder: self-attention with no causal mask. The input is fully known, so every source token may look at every other, left and right. It runs once.
    • Decoder: causal self-attention over the output written so far, exactly as in Part B, because the rest of the output does not exist yet.
    • Cross-attention: the same query–key–value computation, with one change. The queries come from the decoder, while the keys and values come from the encoder’s output. In the library analogy, the readers are in one building and the books in another.

    The equations, and the reasoning behind them

    The question: how does the decoder read the source sentence? It already has a tool for “one set of vectors gathers information from another set”: attention. The only change is where the three inputs come from. The decoder is the one asking, so it supplies the queries. The encoder holds the answers, so it supplies the keys and values.

    Let X_{\text{dec}} be the decoder’s vectors, shape [T_tgt, d_model], and X_{\text{enc}} the encoder’s output, shape [T_src, d_model].

    Q=X_{\text{dec}}W_Q,\qquad K=X_{\text{enc}}W_K,\qquad V=X_{\text{enc}}W_V
    \mathrm{CrossAttention}(X_{\text{dec}},X_{\text{enc}})=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V

    Compare with : the formula is identical. Q has T_{\text{tgt}} rows and K has T_{\text{src}} rows, so the weight table QK^{\top} has shape [T_tgt, T_src]: a rectangle, not a square.

    Why no causal mask here?
    The mask exists to hide tokens that have not been produced yet. The whole source sentence is known before decoding starts, so nothing in it is “in the future”, and every decoder position may read all of it.

    A decoder block therefore has three sublayers, each an update added to the stream:

    \begin{aligned}x' &= x + \mathrm{MaskedSelfAttention}(\mathrm{LayerNorm}(x))\\ x'' &= x' + \mathrm{CrossAttention}(\mathrm{LayerNorm}(x'),\,X_{\text{enc}})\\ y &= x'' + \mathrm{FFN}(\mathrm{LayerNorm}(x''))\end{aligned}

    First look at what has been written so far, then consult the source, then process the result. This is written in the pre-norm style of for consistency; the 2017 paper normalised after each addition instead, as shown further down.

    Worked example: the decoder is about to write “black”

    To write “black”, the decoder asks the encoder “which source word should I translate now?”. The answer is mostly “noir” (61%), with some weight on “chat” (22%), the noun that “noir” describes. French puts the adjective after the noun and English before it, and cross-attention handles the swap without any special rule.

    In Python: cross-attention
    Runs on its own · Python 3 + NumPy
    import numpy as np


def softmax(S, axis=-1):
    e = np.exp(S - S.max(axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)


def attention(Q, K, V):              # the same function as self-attention
    A = softmax(Q @ K.T / np.sqrt(Q.shape[-1]))
    return A @ V, A


source = ["le", "chat", "noir", "dort"]           # encoder side
written = ["<s>", "the", "black"]                 # decoder input so far
Q_dec = np.array([[2, 1, 0, 0], [0, 0, 2, 0], [0, 2, 0, 0]], dtype=float)
K_enc = np.array([[2, 0, 0, 0], [0, 2, 1, 0], [0, 1, 2, 0], [0, 0, 0, 2]],
                 dtype=float)
V_enc = np.array([[1, 0, 0, 0.5], [0, 2, 0, 1], [0, 0, 2, -1], [0.5, 1, 0, 2]])

# Queries from the decoder; keys and values from the encoder. No causal mask.
context, weights = attention(Q_dec, K_enc, V_enc)
print("weights shape:", weights.shape, "= [T_tgt, T_src], a rectangle")

i = 1                                             # decoder has written "the"
print("after 'the', alpha =", weights[i].round(4))
print("context c         =", context[i].round(4))
print("most attended     =", source[weights[i].argmax()])
for word, row in zip(written, weights):
    print(f"query from {word!r:8} attends most to {source[row.argmax()]!r}")

    Contrast with the decoder-only design

    A decoder-only model has no encoder and no cross-attention. To translate, it puts the source and the target in one sequence, “le chat noir dort <s> the black cat …”, and relies on ordinary causal self-attention. The target tokens can still look back at the source tokens, so the job cross-attention did is absorbed into self-attention. The widget below shows who may attend to whom in each design.

    What just happened? In the encoder–decoder view there are three separate tables, each with its own weights. In the decoder-only view the same three kinds of connection appear as regions of a single lower-triangular table, computed by one set of attention weights. One region shrinks: source tokens can no longer see later source tokens, because the single causal mask applies to them too.

    Neither design is strictly better. Encoder–decoder models fit tasks with a clear input and a clear output, such as translation or speech recognition, and give the input a bidirectional reading. Decoder-only models are simpler, treat every task as “continue this text”, and can be pretrained on raw text with no input–output pairs, which is a large part of why they became the default for general-purpose LLMs.

    The 2017 paper, and what came after

    This design comes from the 2017 paper “Attention Is All You Need”, which built it for translation. Its base model had 6 encoder layers and 6 decoder layers, d_{\text{model}}=512, 8 attention heads and an MLP of width 2,048. The attention and multi-head formulas of and are the paper’s own, and no model since has changed them.

    Other details did change. The paper normalised after each residual addition, which is called post-norm:

    x\leftarrow\mathrm{LayerNorm}\big(x+\mathrm{Sublayer}(x)\big)

    In the pre-norm block of , the stream is left alone and only a copy is normalised. Here the stream itself is normalised after every addition, so no untouched path runs from the first layer to the last. That makes deep stacks harder to train, which is why later models moved the normalisation. The table lists the other differences.

    2017 TransformerTypical GPT-style LLM
    StructureEncoder + decoder with cross-attentionDecoder only
    TaskTranslation, trained on sentence pairsNext-token prediction on raw text, then fine-tuning
    NormalisationAfter the residual add (post-norm)Before the sublayer (pre-norm), often RMSNorm, plus a final normalisation
    ActivationReLUGELU (GPT-2, GPT-3) or a gated MLP such as SwiGLU (Llama, Qwen, Mistral)
    PositionsFixed sinusoids added to the inputLearned (GPT-2, GPT-3) or rotary, applied inside attention (most current models)
    Size65 to 213 million parametersBillions of parameters and beyond
    DecodingBeam searchSampling with temperature, top-k, top-p
    UnchangedScaled dot-product attention, multiple heads, residual connections, layer normalisation, a position-wise feed-forward network, learned embeddings, warm-up

    The line of descent is short. In 2018, GPT kept only the decoder and pretrained it on unlabelled text. BERT kept only the encoder and pretrained it by filling in masked words. Scaling the decoder-only branch, with the handful of adjustments in the table, leads to the models in the rest of this guide.

    The paper’s learning-rate schedule. One more idea from the paper became standard: start with a tiny learning rate, raise it for a fixed number of warm-up steps, then let it fall slowly.

    \eta(\text{step})=d_{\text{model}}^{-0.5}\cdot\min\!\left(\text{step}^{-0.5},\ \ \text{step}\cdot\text{warmup}^{-1.5}\right)

    \eta is the learning rate (the paper calls it lrate). \text{step} counts training steps from 1. \text{warmup} is a fixed number of steps, 4000 in the paper.

    Reading the formula.
    The \min chooses between two candidates. \text{step}\cdot\text{warmup}^{-1.5} is a straight line rising from zero; it is the smaller one early on. \text{step}^{-0.5} is a slowly falling curve; it is the smaller one later. They are equal exactly when \text{step}=\text{warmup}, which is where the rate peaks. The factor d_{\text{model}}^{-0.5} gives wider models smaller steps. The gentle start stops a randomly initialised model from being thrown off course by its first, very noisy gradients.

    Worked example: the learning-rate schedule

    The learning rate starts almost at zero, climbs in a straight line for 4,000 steps to about 0.0007, then slides down slowly. By the end of training it is a fifth of its peak.

    Work through the exact numbers

    Base model, d_{\text{model}}=512, \text{warmup}=4000. First, 512^{-0.5}=0.044194.

    At step 1 the second term of the minimum is smaller: 1\times4000^{-1.5}=3.9528\times10^{-6}, so \eta=0.044194\times3.9528\times10^{-6}=1.747\times10^{-7}.

    At step 4000 the two terms are equal, 4000^{-0.5}=0.015811, and the rate peaks: \eta=0.044194\times0.015811=6.988\times10^{-4}.

    At step 100,000: 100000^{-0.5}=0.0031623, so \eta=0.044194\times0.0031623=1.398\times10^{-4}, one fifth of the peak.

    In Python: the learning-rate schedule, post-norm and pre-norm
    Runs on its own · Python 3 + NumPy
    import numpy as np


def paper_lr(step, d_model=512, warmup=4000):
    return d_model ** -0.5 * min(step ** -0.5, step * warmup ** -1.5)


for step in (1, 4000, 100_000):
    print(f"step {step:>7,}: lr = {paper_lr(step):.4g}")
print("peak = (d_model * warmup) ** -0.5 =", round((512 * 4000) ** -0.5, 7))


def layer_norm(x, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)
    return (x - mu) / np.sqrt(x.var(axis=-1, keepdims=True) + eps)


def post_norm(x, sublayer):          # 2017 paper: normalise after the add
    return layer_norm(x + sublayer(x))


def pre_norm(x, sublayer):           # GPT-style: normalise a copy first
    return x + sublayer(layer_norm(x))


rng = np.random.default_rng(0)
W = rng.normal(0, 0.1, size=(8, 8))
sublayer = lambda x: np.tanh(x @ W)
x = rng.normal(3, 2, size=(4, 8))

print("post-norm stream: mean", post_norm(x, sublayer).mean().round(3),
      "std", post_norm(x, sublayer).std().round(3), "(rescaled every layer)")
print("pre-norm stream:  mean", pre_norm(x, sublayer).mean().round(3),
      "std", pre_norm(x, sublayer).std().round(3), "(the input passes through)")

    Common misconceptions

    • “Cross-attention needs a causal mask.” It does not. The whole source is available from the start. Only the decoder’s self-attention is masked.
    • “The encoder runs again for every generated token.” It runs once. Its output is fixed and reused by every decoder step.
    • “Decoder-only models cannot translate or summarise.” They can: the source goes in the prompt and self-attention reaches back to it.
    • “Cross-attention is a different mechanism.” It is the same scaled dot-product attention, with queries from one sequence and keys and values from another.
    • Pitfall: each kind of attention has its own W_Q, W_K, W_V. The decoder’s self-attention and cross-attention do not share weights.
    • “Modern LLMs use the paper’s architecture as written.” The core is intact, but normalisation placement, activation, positional scheme and overall structure have all changed.
    • Pitfall: code or diagrams that follow the paper (post-norm, encoder–decoder) do not match GPT-style code (pre-norm, decoder-only). Check which one a tutorial describes before comparing details.

    Key takeaways

    • The encoder reads the whole source with unmasked self-attention; the decoder writes the target with masked self-attention.
    • Cross-attention: Q from the decoder, K and V from the encoder. Same formula as before.
    • Its weight table is a rectangle, [T_tgt, T_src], and needs no causal mask.
    • Decoder-only models do the same job by putting source and target in one sequence.
    • The 2017 model was an encoder–decoder with post-norm, ReLU and sinusoidal positions. Its attention formulas are unchanged in every model since.
    • GPT kept the decoder and BERT kept the encoder; scaling the decoder-only branch led to today’s LLMs.

    Rotary position embeddings (RoPE)

    The problem. “The cat” means the same at the start of a document and deep inside it. So what attention needs is how far apart two tokens are, more than where each one sits. Adding a position vector to the input () mixes position into everything, and leaves the model to work out distances for itself.

    The change. RoPE adds nothing to the input. Instead, inside every attention layer, it rotates each query and each key by an angle that grows with the token’s position.

    Why that works. Split a vector into pairs of numbers, and treat each pair as an arrow in a plane. Turning an arrow does not change its length. Turn the query at position i by i\omega and the key at position j by j\omega. The angle between them then changes by (i-j)\omega, so their dot product depends only on the distance i-j. For one pair (x_1,x_2):

    \operatorname{RoPE}(x_1,x_2;\,i)=\left(x_1\cos i\omega-x_2\sin i\omega,\ \ x_1\sin i\omega+x_2\cos i\omega\right),\qquad \omega_f=10000^{-2f/d_k}

    i is the token’s position. \omega is the pair’s rotation speed, and each pair f=0,1,\dots,d_k/2-1 has its own. The first pairs turn quickly and tell neighbours apart. The last pairs turn slowly and carry long-range position. Queries and keys are rotated; values are not.

    Llama 3 uses a base of 500,000 instead of 10,000. That slows every pair down, which helps with long contexts.

    What just happened? Each arrow is turned by its position times the pair’s speed. Moving both positions by the same amount turns both arrows equally. The angle between them stays the same, and so does the score: only the distance matters. A fast pair turns a lot between neighbouring positions. A slow pair hardly moves over dozens of tokens, so it can still compare tokens that are far apart.

    RMSNorm

    The problem. LayerNorm () does four things to each vector: it subtracts the mean, divides by the standard deviation, then scales and shifts. Experiments found that not all of that is needed.

    The change. RMSNorm only divides by the root mean square, then scales. There is no mean and no shift. Current models place it before each sublayer (pre-norm).

    The gain. Less work per token, and models train as well. So most current models use it.

    \operatorname{RMSNorm}(x)=\gamma\odot\frac{x}{\sqrt{\frac{1}{d_{\text{model}}}\sum_i x_i^2+\epsilon}}

    \gamma is the learned gain and \epsilon a small constant, as in LayerNorm.

    SwiGLU

    The problem. The 2017 MLP is simple: one projection, a ReLU, another projection. Later experiments found a design that learns more for the same compute.

    The change. A gated MLP computes two projections of the input. One of them, passed through a smooth switch function called SiLU, decides how much of the other gets through, element by element. This is SwiGLU.

    The gain. A lower loss for the same compute. This is an empirical finding, not something derived.

    \operatorname{FFN}(x)=\left(\operatorname{SiLU}(xW_1)\odot xW_3\right)W_2,\qquad \operatorname{SiLU}(z)=z\cdot\operatorname{sigmoid}(z)

    W_1 and W_3 are [d_model, d_ff], and W_2 is [d_ff, d_model]. Three matrices instead of two would add parameters, so models choose a smaller d_{\text{ff}} than 4d_{\text{model}}. Llama 3.1 8B uses 14,336, which is 3.5 times 4,096.

    Grouped-query attention (GQA)

    The problem. The KV cache () stores a key and a value for every head, in every layer, for every token. At long contexts it grows bigger than the model’s weights.

    The change. Do all the heads need their own keys and values? Experiments say no. In grouped-query attention the query heads are split into groups, and each group shares one key head and one value head. Multi-query attention is the extreme case: one key and value head for all.

    The gain. Queries keep all their heads, so the model still looks for many different things. Only what is stored shrinks:

    M_{\text{KV}}=2\times L\times T\times n_{\text{kv}}\times d_k\times\text{bytes per number}\times B

    n_{\text{kv}} is the number of key and value heads per layer. GQA divides the cache by h/n_{\text{kv}}. With n_{\text{kv}}=h this is ordinary multi-head attention, and the cache formula used earlier in the guide, since h\,d_k=d_{\text{model}}.

At long contexts the multi-head cache is several times the weights, which is why nearly every current model uses GQA.

    Mixture of experts (MoE)

    The problem. A model with more parameters can hold more knowledge, but in an ordinary model every token passes through every parameter. Twice the parameters means twice the work per token.

    The change. A mixture-of-experts layer replaces the single MLP with many smaller MLPs, the experts, and a small router. For each token, in each layer, the router scores the experts, keeps the few best and blends their outputs:

    \operatorname{MoE}(x)=\sum_{e\in\mathcal{S}(x)}g_e(x)\,\operatorname{FFN}^{(e)}(x),\qquad g(x)=\operatorname{softmax}\!\big(\text{router scores of the chosen experts}\big)

    \mathcal{S}(x) is the set of experts chosen for this token: usually 1 to 8 out of n_{\text{experts}}, which is often 8 to 128. g_e is expert e’s gate, and the gates add up to 1. \operatorname{FFN}^{(e)} is expert e’s MLP.

    Training adds a small extra loss that keeps tokens spread across the experts. Without it, the router tends to send everything to a favourite few.

    The gain, and the cost. Each token passes through only the chosen experts, so compute and the bytes read per token follow the active parameter count. But any token may be sent to any expert, so every expert must be in memory: memory follows the total count. That is why the mixture-of-experts models in are fast for their size but still need a lot of memory.

    Worked example: one token, two experts

    Four experts score 2.0, 0.5, 1.2 and −0.3 for a token. The two best, experts 1 and 3, are run, and their outputs are blended about 69% to 31%. The other two experts do nothing for this token.

    Work through the exact numbers

    The router gives a token the scores [2.0,\;0.5,\;1.2,\;-0.3] for four experts, and the layer keeps the top 2: experts 1 and 3.

    Gates: \operatorname{softmax}([2.0,\;1.2])=\big[\tfrac{e^{0.8}}{e^{0.8}+1},\;\tfrac{1}{e^{0.8}+1}\big]=[0.690,\;0.310].

    Output: 0.690\,\operatorname{FFN}^{(1)}(x)+0.310\,\operatorname{FFN}^{(3)}(x). Experts 2 and 4 do no work for this token.

Balancing brings the busiest expert down to about 1.2 times the average. That is the job of the balancing loss described above.

    In Python: RoPE, RMSNorm, SwiGLU, grouped-query attention and a router
    Runs on its own · Python 3 + NumPy
    import numpy as np

rng = np.random.default_rng(0)
d_model, h, n_kv, T = 64, 8, 2, 6
d_k = d_model // h


def rms_norm(x, gain, eps=1e-6):
    # LayerNorm without the mean subtraction and without the shift
    return gain * x / np.sqrt((x ** 2).mean(-1, keepdims=True) + eps)


def silu(z):
    return z / (1 + np.exp(-z))


def swiglu(x, W1, W3, W2):
    # one projection is passed through SiLU and gates the other, element by element
    return (silu(x @ W1) * (x @ W3)) @ W2


def rope(x, positions, base=10000.0):
    # rotate each pair of dimensions (2f, 2f+1) by the angle position * omega_f
    omega = base ** (-np.arange(0, x.shape[-1], 2) / x.shape[-1])
    angle = positions[:, None] * omega
    x1, x2 = x[..., 0::2], x[..., 1::2]
    out = np.empty_like(x)
    out[..., 0::2] = x1 * np.cos(angle) - x2 * np.sin(angle)
    out[..., 1::2] = x1 * np.sin(angle) + x2 * np.cos(angle)
    return out


# RoPE: the score depends only on how far apart the query and the key are
q, k = rng.normal(size=d_k), rng.normal(size=d_k)
score = lambda i, j: rope(q[None], np.array([i]))[0] @ rope(k[None], np.array([j]))[0]
print(f"score(10, 7) = {score(10, 7):.4f}, score(103, 100) = {score(103, 100):.4f}")

# Grouped-query attention: 8 query heads share 2 key/value heads
X = rms_norm(rng.normal(size=(T, d_model)), np.ones(d_model))
Wq = rng.normal(size=(d_model, h * d_k)) / 8
Wk, Wv = (rng.normal(size=(d_model, n_kv * d_k)) / 8 for _ in range(2))
pos = np.arange(T)
Q = rope((X @ Wq).reshape(T, h, d_k).transpose(1, 0, 2), pos)       # [h, T, d_k]
K = rope((X @ Wk).reshape(T, n_kv, d_k).transpose(1, 0, 2), pos)    # [n_kv, T, d_k]
V = (X @ Wv).reshape(T, n_kv, d_k).transpose(1, 0, 2)
K, V = np.repeat(K, h // n_kv, axis=0), np.repeat(V, h // n_kv, axis=0)
s = Q @ K.transpose(0, 2, 1) / np.sqrt(d_k) + np.triu(np.full((T, T), -np.inf), 1)
a = np.exp(s - s.max(-1, keepdims=True))
out = (a / a.sum(-1, keepdims=True)) @ V
print("queries", Q.shape, "cached keys per layer", (n_kv, T, d_k), "output", out.shape)

d_ff = 3 * d_model
W1, W3 = (rng.normal(size=(d_model, d_ff)) / 8 for _ in range(2))
W2 = rng.normal(size=(d_ff, d_model)) / 8
print("SwiGLU output", swiglu(X, W1, W3, W2).shape)

# KV cache for the Llama 3.1 8B shape: 32 layers, 32 query heads, 8 KV heads of width 128
for name, heads in (("multi-head", 32), ("grouped-query", 8), ("multi-query", 1)):
    per_token = 2 * 32 * heads * 128 * 2                                # keys and values, 2 bytes
    print(f"{name:13}: {per_token / 1024:4.0f} KiB per token, "
          f"{per_token * 131072 / 1e9:5.1f} GB for 131,072 tokens")

# Mixture of experts: a router picks 2 of 8 experts for each token
router = rng.normal(size=(d_model, 8)) / 8
logits = X @ router
top = np.argsort(-logits, axis=1)[:, :2]
gates = np.exp(np.take_along_axis(logits, top, 1))
gates /= gates.sum(1, keepdims=True)
print("experts chosen for each token:", top.tolist())

    Common misconceptions

    • “RoPE adds a position vector to the embeddings.” Nothing is added to the input. Queries and keys are rotated inside every attention layer; values are not.
    • “GQA means fewer attention heads.” Queries keep all their heads. Only keys and values are shared.
    • “A mixture-of-experts model sends each question to one expert model.” Routing happens for every token in every layer, and the experts are MLPs inside one model, not separate models.
    • “These changes make a different kind of model.” It is still a decoder-only Transformer trained on next-token prediction; the changes are refinements for cost and stability.

    Key takeaways

    • RoPE rotates queries and keys by their positions, so attention scores depend on the distance between tokens.
    • RMSNorm drops LayerNorm’s mean and shift; SwiGLU gates the MLP; both are cheaper or better for the same compute.
    • GQA shares key and value heads between query heads and divides the KV cache by h/n_{\text{kv}}.
    • A mixture-of-experts model needs memory for all its parameters but computes only with the active ones.

    Check yourself

    32 ÷ 8 = 4 query heads share each key and value head.

    3. A mixture-of-experts model has 46.7B parameters, 12.9B active per token. What does it need memory for?

    Multimodal LLMs: how a model reads images

    Builds on Embeddings from , , and the model families in .

    Show the model a photo of a cat on a mat and ask “What is the cat sitting on?”. The answer “mat” is still the next-token prediction you have followed all along. The only change is that some of the input tokens came from the photo instead of from text.

    A multimodal LLM accepts more than one kind of input: usually text and images, and sometimes audio or video. Most current assistants are multimodal. What is surprising is how little changes. The Transformer reads a sequence of vectors, and it does not care where the vectors came from. So the whole job is to turn an image into vectors of the right width.

    From pixels to tokens

    1. Cut the image into a grid of square patches, for example 14 × 14 pixels each.
    2. Flatten each patch into one list of numbers: 14 × 14 pixels × 3 colours (red, green, blue) = 588 numbers.
    3. Project that list to the model’s width by multiplying it by a learned matrix. This does the job of the embedding table: a text token’s vector is looked up, a patch’s vector is computed.
    4. Add position, which for an image has two directions: the row and the column of the patch.

    This is the recipe of the Vision Transformer (ViT), from a 2020 paper titled “An image is worth 16×16 words”.

    Imagepixels
    →
    Patchesflatten, project, add position

    Vision encodera Transformer

    How many tokens does an image cost? One per patch. The patches form a grid, so count the patches along each side and multiply:

    \text{image tokens}=\frac{\text{height}}{\text{patch}}\times\frac{\text{width}}{\text{patch}}

    Height and width are in pixels. Patch is the side of one patch in pixels. Halving the patch size doubles both fractions, so it multiplies the tokens by 4.

    How does a patch become a vector? Exactly as a layer does in : a row of numbers times a matrix.

    \text{patch vector}=\operatorname{flatten}(\text{patch})\;W_{\text{patch}}

    \operatorname{flatten}(\text{patch}) is the patch’s pixel values in one row: 588 numbers for a 14-pixel patch. W_{\text{patch}} is a learned matrix with 588 rows and d_{\text{model}} columns. The result is one vector of width d_{\text{model}}, the same width as a text token’s.

    Worked example: the cost of one photo

    A 336 × 336 image cut into 14-pixel patches makes a 24 × 24 grid: 576 image tokens. The question about it is about 8 tokens, so the image is around 70 times longer. A large image cut into tiles can cost thousands of tokens.

    Work through the exact numbers

    A 336 × 336 image with 14-pixel patches: 336/14=24 patches per side, so 24\times24=576 image tokens. Each patch is 14\times14\times3=588 numbers before projection.

    The question “What is the cat sitting on?” is about 8 text tokens. The image is about 70 times longer than the question.

    A model that reads a 1,344 × 1,344 image by cutting it into 336-pixel tiles needs 4\times4=16 tiles, so 16\times576=9{,}216 tokens, before any extra overview image.

    The three parts of a vision-language model

    1. A vision encoder. A Transformer that reads the patch vectors, with no causal mask, so every patch can attend to every other. Its output vectors describe what is in each part of the image. It is often trained first on its own, in the style of CLIP (2021): given hundreds of millions of images with their captions, learn embeddings in which an image and its own caption are close (high cosine similarity) and mismatched pairs are far apart.
    2. A projector. A small MLP, sometimes a single matrix, that maps the encoder’s vectors to the LLM’s width.
    3. The LLM. The decoder-only Transformer of . The image tokens sit in the prompt where the image was placed, among the text tokens. With the causal mask, every text token after the image can attend to all of the image tokens.

    Training. A common recipe takes a pretrained vision encoder and a pretrained LLM, and connects them in two stages. First, only the projector is trained, on images with captions, so that image tokens start to land where the LLM expects meaningful vectors. Then the projector and the LLM are fine-tuned together on conversations about images. As in , the loss counts only the tokens of the answer. Some models are instead trained on images and text together from the start.

    Other inputs, and images as output

    • Audio. Sound is turned into a spectrogram, the strength of each frequency over time, and short slices of it become tokens. Speech recognisers such as Whisper read them with an encoder–decoder Transformer ().
    • Video. A few frames per second are sampled and each frame is cut into patches. The token count climbs fast, so models sample frames sparingly and merge neighbouring patches.
    • Images as output. Reading an image is not the same as making one. Some systems pass the request to a separate image generator, usually a diffusion model (). Others generate image tokens one at a time and decode them back into pixels.

    Common misconceptions

    • “The model first describes the image in words, then reads the description.” The image tokens go straight into the sequence as vectors. No caption is written in between.
    • “An image costs about as much as a word.” It costs hundreds to thousands of tokens, which count against the context window and the price.
    • “The model sees every pixel at full resolution.” Large images are resized or tiled to a budget. Small print in a big image can be lost before the model reads it.
    • Pitfall: sending every image at the highest resolution by default. Check how your provider counts image tokens, and test whether a smaller image gives the same answers.

    Key takeaways

    • An image becomes tokens by cutting it into patches, flattening each patch, and projecting it to the model’s width.
    • Image tokens = (height ÷ patch) × (width ÷ patch); halving the patch size multiplies them by 4.
    • A vision-language model is a vision encoder, a projector and an LLM; the LLM reads image and text tokens in one sequence.
    • Images are expensive: hundreds to thousands of tokens each.

    How diffusion models make images

    Builds on The two recipes in , the training loop in , and cross-attention from .

    Ask an image model for “a cat sitting on a mat”. It does not draw the cat stroke by stroke, the way an LLM writes the sentence token by token. It starts from a screen of random static and, in a few dozen steps, cleans it up until a cat on a mat is all that is left.

    An LLM builds its output one piece at a time. A diffusion model works on the whole output at every step: it starts from pure noise and removes a little of it each time. The idea is easiest to follow in two halves: how the model is trained, and how it is then used to generate.

    Training: add noise, learn to predict it

    Step 1: make noisy examples. Take a clean training image and mix it with random noise. A noise level controls the mix: at the lowest level the image is untouched, at the highest it is pure noise. Training uses every level, so the network learns to clean images that are slightly noisy and images that are almost all noise.

    u_{\text{noisy}}=\sqrt{\bar\alpha}\,u_0+\sqrt{1-\bar\alpha}\;\varepsilon

    u_0 is the clean example: every pixel value of the image in one list. u_{\text{noisy}} is the same example at a chosen noise level. \varepsilon is random noise of the same size, drawn fresh each time from a normal distribution. \bar\alpha is the share of the original kept, set by the noise level: 1 for a clean example, close to 0 for pure noise.

    Why the square roots?
    The square roots keep the overall size of the values the same at every level. The variance of the mix is \bar\alpha times the image’s variance plus 1-\bar\alpha times the noise’s, and with both scaled to 1 that is always 1. So the network always sees inputs of the same scale, whatever the noise level.

    Step 2: predict the noise. We know exactly which noise we added, so we can ask the network to recover it. That is ordinary supervised learning: the input is the noisy image and its noise level, the right answer is the noise, and the loss is the mean squared error.

    \mathcal{L}=\big\lVert\,\varepsilon-\varepsilon_\theta(u_{\text{noisy}},\,\text{level},\,\text{prompt})\,\big\rVert^2

    \varepsilon_\theta is the network, with parameters \theta; its output is its guess at the noise. The network is also told the noise level and, in a text-to-image model, given the prompt. \lVert\cdot\rVert^2 is the sum of the squared differences.

    Generating: remove a little noise, many times

    To make a new image, start from pure noise at the highest noise level. At each step:

    1. The network predicts the noise, \hat\varepsilon.
    2. Undo the mixing formula to get a guess at the clean image:
    \hat u_0=\frac{u_{\text{noisy}}-\sqrt{1-\bar\alpha}\;\hat\varepsilon}{\sqrt{\bar\alpha}}
    1. Do not jump to that guess. Move to the next, slightly lower noise level, part of the way towards it, with a little fresh noise. Then repeat.

    \hat\varepsilon is the predicted noise and \hat u_0 the current guess at the clean image; the hat marks an estimate.

    Why not jump straight to the guess? From pure noise, the clean image could have been almost anything. The network’s best single guess is then the average of everything it could have been: a grey blur. Each small step commits to a little more detail, and lowers the noise so that the next guess can be sharper. Too few steps, and the blur stays.

    Worked example: one pixel, noised and cleaned

    A pixel of 0.8 mixed with noise becomes −0.26. If the network predicts the noise exactly, undoing the mix gives back 0.8. If its prediction is off by a third, the guess comes out at about 0.43 instead. Small steps let later, less noisy predictions fix such errors.

    Work through the exact numbers

    A clean pixel u_0=0.8, noise \varepsilon=-1.5, and a level with \bar\alpha=0.64, so \sqrt{\bar\alpha}=0.8 and \sqrt{1-\bar\alpha}=0.6.

    Noised: u_{\text{noisy}}=0.8\times0.8+0.6\times(-1.5)=0.64-0.9=-0.26.

    If the network predicts the noise exactly, \hat\varepsilon=-1.5: \hat u_0=(-0.26+0.9)/0.8=0.8, the original.

    If it predicts \hat\varepsilon=-1.0: \hat u_0=(-0.26+0.6)/0.8=0.425. An error of 0.5 in the noise moves the guess by about 0.375. That is why the model takes small steps and keeps correcting.

    u = rng.normal(size=(n, 2))                       # start from pure noise
    for k in range(steps, 0, -1):
        a, a_next = alpha_bar(k / steps), (alpha_bar((k - 1) / steps) if k > 1 else 1.0)
        u0_hat = guess_clean(u, a)
        eps_hat = (u - np.sqrt(a) * u0_hat) / np.sqrt(1 - a)
        sigma = np.sqrt((1 - a_next) / (1 - a) * (1 - a / a_next))
        u = np.sqrt(a_next) * u0_hat + np.sqrt(max(0.0, 1 - a_next - sigma**2)) * eps_hat \
            + sigma * rng.normal(size=u.shape)        # move towards the guess, add a little fresh noise
    return u


for steps in (1, 3, 10, 50):
    u = generate(steps)
    dist = np.sqrt(((u[:, None] - data[None]) ** 2).sum(-1)).min(1)
    print(f"{steps:2} step{'s' if steps > 1 else ' '}: spread {u.std(0).mean():.2f}, "
          f"on the spiral {np.mean(dist < 0.03):4.0%}")

    Interactive · from noise to a spiral

    The point: Diffusion turns noise into data by many small steps, and the number of steps decides the quality. Do this: With 50 steps, press Generate and watch the cloud. Then try 10, 3 and 1. Finally, choose “Add noise” and drag the slider to see the examples that training uses. Watch for: The ringed sample and its × (its current guess at a clean point); and, with 1 step, every sample landing on the same spot.

    Direction
    Steps
    · grey: the 300 training points● samples◯ one sample, × its current guess
    What is simplified: each example is two numbers (a point) instead of a million pixel values, and the training data are 300 points on a spiral. The denoiser is not a trained network: it is the best possible guess for these 300 points, computed by formula as a weighted average of them. A real model learns to approximate that guess with a network, and cannot match it exactly; that imperfection is part of what lets it make new images rather than copies of its training set.
    What just happened? At each step every sample asked which training points it could have come from, moved part of the way towards their average, and received a little fresh noise. With lots of noise the answer is “almost anywhere”, so the × sits near the middle of the data. As the noise falls, it narrows to one part of the spiral. With 1 step, every sample jumps straight to its first guess, the average of all the training points, so they all land on one spot: the toy version of a blurry image. With 3 steps they spread out but mostly miss the spiral; with 10, about three in four land on it; with 50, nearly all do, and together they cover the whole spiral. Fewer steps are faster but worse, which is why fast image models need extra training to work in only a few steps.

    Steering with a prompt

    A text-to-image model passes the prompt through a text encoder, a Transformer like the ones in this guide, and gives the resulting vectors to the denoising network at every step. Inside the network, cross-attention () lets every part of the image read from the prompt’s tokens, just as the decoder read from the source sentence in translation.

    Guidance. On its own the condition steers only weakly. Classifier-free guidance runs the network twice per step, once with the prompt and once without, and pushes the prediction further in the direction the prompt made it move:

    \hat\varepsilon=\hat\varepsilon_{\text{without}}+\gamma\,\big(\hat\varepsilon_{\text{with}}-\hat\varepsilon_{\text{without}}\big)

    \gamma is the guidance scale. With \gamma=1 this is the ordinary prediction with the prompt; larger values follow the prompt more closely at some cost to variety. Values around 5 to 8 are common.

    Where the Transformer fits

    • The text encoder that reads the prompt is a Transformer.
    • The denoising network was at first a convolutional network (a U-Net) with attention layers added. Many newer models use a Transformer instead: the noisy image is cut into patches, exactly as in , and the patches are the tokens.
    • Latent diffusion. Denoising every pixel of a large image is expensive, so most models first compress the image with a separate network (an autoencoder) to a grid several times smaller in each direction, run diffusion there, and decode the result back to pixels at the end.

    Common misconceptions

    • “The model searches its training images and blends them.” No images are stored. The network has learned to predict noise, and the image emerges from many of those predictions.
    • “Diffusion means a different kind of network.” Diffusion is the recipe. The network inside can be a convolutional network or a Transformer.
    • “More steps always means a better image.” Quality improves quickly at first and then levels off; past a point, extra steps only cost time.
    • Pitfall: treating the same prompt as giving the same image. A different starting noise gives a different image; fix the random seed to reproduce one.

    Key takeaways

    • Training mixes clean examples with noise at random levels and teaches a network to predict the noise.
    • Generating starts from pure noise and removes a little of the predicted noise at each of many steps.
    • One big step gives the average of all possible images, a blur; many small steps let detail emerge.
    • The prompt steers each step through cross-attention, and the denoising network is now often a Transformer over image patches.

    Check yourself

    1. During training, what is the diffusion network asked to predict?

    The noise was added on purpose, so the right answer is known, and the loss is the squared error of the guess.

    2. In the interactive, why do all samples land on one spot with a single step?

    Pure noise says almost nothing about where a sample came from, so every guess is the same average. With images, that average is a blur.

    3. How does a text-to-image model let the image follow the prompt?

    The prompt’s vectors are read through cross-attention in every step.
